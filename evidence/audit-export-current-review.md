# Export runtime and recovery review corrections

This correction covers PR #1874 export denial and restored authorization findings. Every audit RPC refusal caused by a locked current member lacking audit permission must reach the shared denial guard before any denial row is committed. That guard appends at most one event for each admitted denial, consumes its limiter reservation, and returns FORBIDDEN. The export request and export status paths now share AuditReadDeniedError from the existing read authorization module; the former router-local class is removed. A disappeared membership is FORBIDDEN without a false member-denial event. The one-use download route retains its uniform unavailable response and is deliberately outside the RPC guard.

Both new actual HTTP regressions fail on prior source with INTERNAL_SERVER_ERROR, then pass after correction. Seven attempts per export endpoint return FORBIDDEN while producing exactly five audit.read_denied events and no export job. This tests both the response and the limiter's persisted effect.

Recovery again deletes restored alert recipients/settings and verifies they remain absent before reopening. Restored tests seed actual settings/recipients and reject reintroduction after reconciliation; both fail on the previous source. All five inventory lookups again use the parent maps/sets, avoiding repeated linear searches over inventories of up to 250,000 rows. Export quarantine and retained artifact cleanup remain additive to those parent protections. Duplicate recovery lock-list table names introduced by integration are removed.

Validation: 45 PostgreSQL/HTTP/export/recovery tests pass; server types, scoped lint and Knip pass. The existing staged-export changeset covers this initial behavior. No migration or production configuration changes are included. Inherited installer release-admission and deployed-lock-verifier findings are being corrected in the installer parent before the complete branch is reviewed again.
