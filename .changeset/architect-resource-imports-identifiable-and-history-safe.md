Architect tells apart two resources that share a filename, keeps operations that change nothing out of the undo history, and keeps the upload control focused when an import cannot go ahead.

**Two files called the same thing are two different cards again.** Uploading `people.csv` twice produced two resources nothing on screen could distinguish: same heading, same badges, same Preview, Download and Delete labels, and the same word to type when searching the library. The Resource Library now shows the second one as `people (2).csv`, in the library, in the resource pickers inside a stage editor, on the selected-resource thumbnails, and in the name it downloads under. This is a display name only: your protocol keeps the filenames you gave your own files, so nothing Architect invented is saved, exported, or handed to Interviewer — and a protocol that already contains resources with matching names is disambiguated when you open it without its file being touched. A resource that really is called `people (2).csv` keeps that name; the derived one counts past it.

**Undo and Redo describe only the changes you actually made.** Adding a file Architect could not read changed no resource, but still enabled Undo: using it announced "Change undone" and undid nothing, then offered a Redo that was just as empty — and, worse, the refusal threw away a resource you had already undone and could still have brought back. The cause turned out to have nothing to do with resources. The check meant to recognise "this changed nothing, so it is not a point in the history" could never be true, so anything that left your protocol exactly as it was took a place in the history and cleared your redo anyway. Clicking into the protocol name and back out without typing did it; so did saving a variable you had not altered, or deleting a resource that was no longer there. Architect now compares what an operation produced against what it was given, whether the operation edits your protocol in place or rebuilds it, so an operation that changed nothing is not something you can undo.

**Dismissing the error leaves you where you started.** The upload control was taken out of the keyboard tab order while the import ran, which made the browser drop focus as soon as it started; the error dialog then had nothing to hand focus back to, and left the control unreachable by Tab for the rest of the session. The control stays reachable throughout — announced as busy while it works — and both the error and the duplicate-rows warning return focus to it when dismissed, whether you activated it or dropped a file onto the page. An acknowledgement dialog anywhere in the app now opens with its own action focused, so what it wants from you is the first thing announced.
