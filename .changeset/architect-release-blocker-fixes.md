This release clears the problems that were holding Architect back: edits that escaped the stage they were made in, a Codebook that disagreed with itself about where a variable was used, editors and a timeline that could not be worked from the keyboard or on a phone, required questions that looked answered when they were not, broken references no check ever caught, and failures that showed you the machinery instead of telling you what happened.

**Editing a stage.** Changes made in a stage's field and variable editors are now held with the stage and applied only when you save it. Cancelling or leaving without saving restores the Codebook exactly as it was, so a renamed variable, a swapped input control, edited options, a new required flag or an orphan variable no longer survives a stage you discarded and spreads to every other stage collecting it. A field whose validation rules are unfinished or impossible to satisfy is no longer saved with the offending rule silently dropped, taking any working value with it: the editor stays open, keeps what you entered, and names the rule it is waiting on. Two option labels that merely look identical are recognised as duplicates, so a participant is not shown two choices with nothing to tell them apart. Changing a date field's resolution still clears its range, but warns first and confirms afterwards. And Cancel and the browser's Back button now raise one discard confirmation between them rather than stacking two.

**Information blocks.** Switching an Information block — or a Family Pedigree intro block, which shares the same editor — between text, image, audio and video no longer destroys what you wrote. Each type keeps its own draft while the window is open, only the type you save is written to the protocol, and each switch is announced. A block whose resource cannot be shown explains why, telling a deleted resource from one that is present but is not an image, audio or video file. Saving an empty block is refused visibly instead of silently.

**Attribute editors.** Editors that ask the same question now answer it the same way. An attribute whose options were fixed when it was created is shown read-only with the reason, rather than offering an edit that could not be saved — one that used to invalidate the whole protocol and strand you on a recovery screen whose only exit discarded the stage you had just made. Attributes an interface owns show their canonical options rather than a copy from the file that may differ, a refused Family Pedigree binding names the interface that owns the attribute, and the Network Composer's input-controls documentation link works again.

**Controls that name themselves.** A stage editor's switches all announced themselves as "Turn this feature on or off" and its add buttons as "Add new"; each is now named by the section it belongs to or the list it adds to, including several that had no name at all. Colour swatches use their palette names rather than internal tokens, and a colour a protocol carries beyond the end of the palette falls back to something visible everywhere it is drawn, instead of painting nothing you could see in order to replace it. Choosing a variable clears the "required" message about not having chosen one; an empty node or edge type name reports one accurate error rather than two; the input-control dropdown is a set of real option groups rather than a flat list punctuated by unselectable headings. The Issues panel labels each problem the way the page labels the field, and takes you to the control that resolves it. Every surface also names an interface the way the New Stage screen does — six were called something different depending on where you met them — and suggested stage names compare two spellings the way the codebook and the schema do.

**Skip logic and filter rules.** The rule editor is now an ordinary Architect form: controls mark themselves required, a save that cannot go through leaves the message on the missing control and moves focus to it, and closing with unsaved work asks first. Ego and alter rules share one whole-number control for a selected-option count, so a rule the protocol rejects can no longer be authored. Each rule card is a single button naming the rule it acts on, rather than the fifth identical "Edit rule" in a list of five; the rules are a real list with a readable "and"/"or"; and the builder answers to its own label, required marker and error message. Skip Logic and Filter name their add buttons separately, and the headings read as English rather than "Choose an node type to base your rule on".

**The Codebook.** "Used In" now lists every place a variable is referenced, so it can no longer disagree with the delete button: prompt sort orders and a roster's card, search and sort columns were missing, so a variable could sit marked in use with an empty column, or be offered for deletion when only a roster read it. The Protocol Summary gains the same references, and both name a stage once rather than once per reference. Entries name the attribute or entity type correctly when a protocol's own names contain a dot, instead of reading "unknown". Refusing to delete an in-use variable says why instead of closing as though it worked, following a "Used In" link leaves focus where it sent you, and a very long variable name no longer pushes Cancel out of its own confirmation. Nothing about a protocol file changes.

**Undo and Redo.** One press now takes back one change wherever you press it; a change made on another page used to take two, the first only moving you there. Architect still brings you to the page that shows the result, in the same press, and says what happened. Both controls are now available on the Summary page, and live in one toolbar at the bottom left of the timeline and the stage editor. Operations that changed nothing — clicking into the protocol name and back out, saving a variable you had not altered, a refused import — no longer take a place in the history or clear your Redo. Delete confirmations for a stage, a codebook variable and a codebook type now say Undo can restore them; the start screen's dialogs are unchanged, because theirs really cannot be undone. Deleting a protocol clears its undo history too, so a full copy of every label, prompt and codebook entry — including anything written while piloting — no longer sits in memory after a dialog promising permanent removal from the device.

**The stage timeline.** Every timeline action now works from the keyboard: a control that opens the stage editor, a grip handle that moves a stage with the arrow keys and announces where it landed, and a delete control. Those controls and the insertion points appear on focus rather than on hover alone, so nobody is operating an invisible Delete, and confirming a deletion hands focus to a neighbouring stage and says what went and how many remain. The list holds its stages and nothing else — a 32-stage protocol used to be announced as a list of 65 things. Rows are fluid rather than a fixed width with the delete button parked outside them, so the page no longer scrolls sideways at tablet and phone widths. Nothing changes for researchers working with a mouse.

**Long names and small screens.** Removing one shared minimum width settled fourteen of Architect's nineteen stage editors; the last six — Name Generator Roster, Geospatial, Family Pedigree, Alter Form, Alter Edge Form and Narrative Pedigree — were each held open by a fixed width of their own, and now fit at phone and tablet width. Selected resource cards, lists of repeatable settings, the pedigree's two-column variable settings and long variable name pills all give way to the space they have; buttons no longer force their container wider, a segmented toolbar scrolls its segments rather than clipping them, and an over-long word breaks rather than overflows. Protocol names are limited to 100 characters, stated before you type and counted as you approach it, and the name on the protocol card is bounded rather than growing until it pushes the timeline off screen. Names you already have still open, still read in full to a screen reader, and are never rewritten or trimmed on your behalf. Right-to-left names are trimmed from the correct end.

**Two tabs on one protocol.** The tab that does not hold the saved copy now shows a read-only view of the whole protocol — still printable and downloadable — instead of an editor whose every change was quietly thrown away and whose resource imports wrote the file into storage under the other tab's protocol. It no longer offers Undo and Redo, which used to rewind the protocol on screen and then drop the write. Closing the other tab hands editing straight back on the same page, reloading the saved copy first. A stage part-way through being edited stays on screen, with a message saying nothing changed there can be saved while the other tab is open and the two things that resolve it. The banner and the leave-and-discard dialogs say what is actually true, including when nothing in this tab is being saved and what discarding takes with it. A `/protocol` address opened with no protocol returns to the start screen instead of an editable "Untitled protocol" that accepted stages, variables and names and saved none of them.

**Resources and files.** Two uploads sharing a filename are told apart as `people (2).csv` in the library, in the pickers, on the thumbnails and in the name it downloads under — a display name only, so your protocol keeps the filenames you gave your own files. The upload control stays reachable while an import runs, announced as busy, and both the error and the duplicate-rows warning return focus to it. Images, videos and rosters no longer accumulate in memory: a file shown in two places at once loads once, closing a preview releases what it was still loading, a re-import no longer breaks the file it just replaced, and deleting a protocol releases its files — including, for a protocol encrypted at rest, their decrypted contents. Download and Save to source run once per intent, so a source save cannot overwrite the protocol source files twice at once. Creating a Mapbox API key applies it to the stage and closes the dialog, instead of leaving the form filled with no confirmation and silently accepting a duplicate.

**Dialogs, menus and keyboard focus.** Closing or cancelling a dialog, or dismissing a picker, returns focus to the control that opened it — including for the confirmations shown during an interview in Interviewer and Fresco. The page behind an open dialog is properly inert to both Tab and screen readers, while status announcements are still heard. Submitting a form with missing values moves focus to the first field that needs attention, including fields whose control is a button or a rich text editor, and never to a hidden element kept beside a visible switch or checkbox. A toolbar control that becomes unavailable while holding focus stays where it is, announced as unavailable, rather than dropping focus to the top of the page. On Architect's start screen, a protocol row's actions menu is finally reachable and operable by keyboard, and See more info, Download or a cancelled Delete return focus to the button you opened it with; the actions button stays available while a download runs.

**In an interview, and in Preview.** A required yes/no question now asks with genuinely unselected Yes and No choices, instead of a switch that already read "No" while refusing to let the participant continue — this reaches protocols already in use as soon as they load, and the same true/false is recorded. A required scale no longer announces a value nobody chose. A blocked submission moves straight to the first unanswered question on screen. Comparison errors name the question the participant was asked rather than the researcher's variable, a blank answer produces one message rather than two, and an unanswered optional question is no longer reported as an invalid email address or as too short, too small or too large. The "scroll to see more questions" callout sits below the questions rather than over them. The quick-add box in a Name Generator and the add-person box in a Network Composer are announced properly again, and the quick-add box says what it is asking for. Rosters and external panels show that they are loading instead of declaring themselves empty before they have been read, and a roster with nothing left to add says so rather than blaming a search nobody typed. Location search returns focus to the search control and announces what it found, including when nothing matched and when the search could not run at all. Editing a person in a Family Pedigree no longer ends the interview screen with an error whose recovery discarded the pedigree built so far. And finishing an interview in Preview now shows a completion screen saying plainly that nothing was saved and offering a fresh run or closing the tab, with a confirmation that states what finishing a preview actually costs.

**What protocol validation now catches.** Variables an interview interface owns — a Family Pedigree's participant marker, how each relative is related, and what kind each relationship is — can no longer be written to from elsewhere in the protocol. A nomination prompt pointed at the participant marker used to bring back several relatives marked as the participant, with the pedigree's completeness checks passing over an unfinished tree; a disease mapped to the same variable painted the participant as affected in every preview. A form can no longer ask for the same variable twice, where both fields shared one answer. A Sociogram can still colour its nodes by such a variable, but can no longer be set up so that tapping a node turns it on and off. A Narrative Pedigree can no longer record two diseases against one variable or under one name, nor map a disease onto a variable the pedigree derives from the family tree. And a Family Pedigree's nomination prompts and family-member form fields, and a Narrative Pedigree's disease mappings, are now checked against the codebook when a protocol is opened, so a reference to a deleted attribute is reported where it is instead of quietly collecting answers into a variable that does not exist, or drawing every relative as unaffected. A protocol that opened yesterday may therefore be reported as invalid today: nothing about it changed, the reference was always broken, and each report names the attribute and takes you to the prompt or field that names it. Architect describes any of these problems in plain language on opening and offers to repair them, saying what each fix will change and writing nothing until you accept; one that cannot be repaired automatically is described rather than opened, so it is never left half-fixed. A pedigree that cannot find the participant in its own tree, or finds several, now says so instead of reporting the tree as complete.

**Messages you can act on.** An unexpected failure while validating a protocol, loading a roster, syncing an interview or importing a protocol now reads as a plain sentence rather than a stack trace pasted into the message. A protocol file that cannot be opened says what is wrong and what to try, with anything technical behind a "Technical details" section, instead of the zip library's own error text — in Interviewer too, where a device that had run out of room used to report a database error. Nothing about your saved protocols changes when an import fails. A protocol that cannot be brought up to date because two attributes on one entity share a name now names the attribute and the entity and says how to resolve it; nothing is renamed automatically, because which one keeps the name is the researcher's decision. A failed download, or a file that could not be added to the resource library, explains itself in a sentence. And in Fresco, a recruitment link whose protocol has been deleted explains that the link is no longer valid instead of showing a generic error page and filing a routine dead link as an application fault.

**Fresco's activity feed, and analytics.** Activity shown in the dashboard feed reaches analytics again — the report used to be scheduled only once the entry had been saved, by which point the request had usually finished and the report was dropped without a trace. Feed entries are held open until they are written, reports queued behind one response no longer cancel each other, and uninstalling a protocol is recorded like every other activity, which matters because that is what invalidates recruitment URLs already given to participants. Analytics no longer receives the feed's written description, which names the researcher who acted and, for interview activity, the participant; only the kind of activity and any counts are sent, and recording activity is no longer reachable from the browser. Across Architect, Interviewer, Fresco and embedded interviews, events now carry the app's name and version, Architect no longer reports local development usage, and Fresco's server-side events are correlated with the browser session that caused them.

For consumers of `@codaco/fresco-ui`: `ArrayField` no longer imposes a minimum
width of its own. It fills the container it is given and shrinks with it, so a
host that previously relied on the field to hold a column open needs to set that
width itself.
