The documentation now covers translated protocols. A new Translating Your
Protocol page explains how to choose the language a protocol is written in,
add and remove languages, set the default language, find missing translations,
translate in the translation table, which shows every text beside its
translation into each language, identify the language of a protocol upgraded
from an earlier version, preview and print each language, and how participants
get their language. It explains that languages have no
order and are always listed alphabetically, that a text needs a translation in
at least one language and a missing translation is only a warning, and how
participants are shown the best available translation of each text: in their
own language or a close regional match, then in the other languages their
browser lists, then in the default language, then in any language that has it.
It explains that node type, edge type, Narrative highlight and Network
Composer field labels are translated while attribute labels are plain text
that participants don't see, and the Narrative and Network Composer pages say
where each label is shown and that every Network Composer field needs a label.
A new page documents the Language Chooser interface, including how to manage
the protocol's languages from its editor in Architect. The preview, Fresco and
Interviewer guides describe how an interview's language follows the
participant's browser rather than a settings menu, the Data Export page and
the Export Data Dictionary describe the new interview language column, and the
schema 9 notes and Fresco upgrade guide describe what the upgrade to schema 9
does to a protocol's text. Pages that listed three interface languages now
list all ten.
