## Introducción {#introduction}

Este tutorial ofrece un ejemplo de flujo de trabajo de importación y análisis de datos de [Network Canvas](https://networkcanvas.com/es/) en el entorno estadístico R con los paquetes [ideanet](https://cran.r-project.org/web/packages/ideanet/index.html) (en inglés) y [egor](https://cran.r-project.org/web/packages/egor/index.html) (en inglés). El ejemplo usa datos simulados a partir del siguiente [archivo de protocolo de Network Canvas](https://github.com/complexdatacollective/working-with-data/raw/main/IJE_RADAR_Protocol.netcanvas), que puede abrirse en las aplicaciones Interviewer o Architect. Si sigues este ejemplo con tu propio protocolo, primero tendrás que exportar los datos recopilados con él. Aquí no explicamos el proceso de exportación, pero te recomendamos consultar la [guía de exportación de datos](/es/analyze-data/data-export) y [Flujos de trabajo de protocolos y datos](/es/collect-data/protocol-and-data-workflows) para ver los detalles. Ten en cuenta que, para este flujo de trabajo, tendrás que exportar los datos con la opción CSV y no con la opción GraphML.

Si no usas tu propio protocolo, puedes descargar [aquí](https://github.com/complexdatacollective/working-with-data/raw/main/networkCanvasExport.zip) los archivos CSV que se usan en este tutorial. Descargar el archivo de protocolo enlazado más arriba es opcional, pero te recomendamos encarecidamente que también lo hagas. El flujo de trabajo de este tutorial usa herramientas capaces de leer archivos de protocolo de Network Canvas y de aprovechar la información que contienen para procesar los datos de forma más eficaz.

Si necesitas más recursos o simplemente tienes curiosidad, puedes encontrar [aquí](https://github.com/complexdatacollective/working-with-data) (en inglés) un repositorio de GitHub completo para este tutorial.

## Localizar tus datos {#locating-your-data}

Tanto si has descargado nuestros datos de ejemplo como si has exportado correctamente tus propios datos, ahora deberías tener en algún lugar de tu ordenador una carpeta con archivos CSV de Network Canvas. El contenido de esta carpeta debería parecerse a la captura de pantalla siguiente (ten en cuenta que, si trabajas con tus propios datos, el principio del nombre de cada archivo probablemente será distinto):

<ImageFullWidth src="/assets/img/working-with-data/nc_directory_list.png" alt="Una carpeta con archivos CSV exportados de Network Canvas"></ImageFullWidth>

Una vez que tengas tus datos, lo primero que tendrás que hacer en R es crear un objeto que guarde la ruta a esta carpeta como un valor de tipo carácter.

```r
# Store path to folder with Network Canvas data
### Note that this path will almost certainly be different on your own computer
path_to_data <- paste0(getwd(),'/networkCanvasExport/')
```

Si vas a usar tu archivo de protocolo de Network Canvas, como te hemos recomendado antes, también tendrás que guardar la ruta al archivo de protocolo en otro objeto.

```r
# Store path to Network Canvas protocol file
### Note that this path will almost certainly be different on your own computer
path_to_protocol <- paste0(getwd(),'/IJE_RADAR_Protocol.netcanvas')
```

## Leer los datos con ideanet {#reading-data-using-ideanet}

Una vez definidas estas rutas, recurre al paquete [`ideanet`](https://cran.r-project.org/web/packages/ideanet/index.html) (en inglés) para cargar tus datos en R. El paquete `ideanet` ofrece una función diseñada específicamente para leer datos recopilados con Network Canvas, llamada `nc_read`. `nc_read` recibe un argumento principal, `path`, un valor de tipo carácter que indica la carpeta que contiene los archivos CSV de Network Canvas que quieres procesar. Si además tienes el archivo del protocolo de Network Canvas con el que se recopilaron tus datos, puedes indicar su ubicación a `nc_read` con el argumento `protocol`. Aunque es opcional, este argumento permite a `nc_read` acceder a información de tu archivo de protocolo que mejora la codificación de las variables categóricas de tus datos. Por lo general, lo más recomendable es usar tu archivo de protocolo con `nc_read` si lo tienes a tu disposición.

Fíjate en que ya has indicado las ubicaciones de los datos (`path_to_data`) y del archivo de protocolo (`path_to_protocol`), así que es fácil continuar con `nc_read`:

```r
# Load `ideanet`
library(ideanet)

# Set up `nc_read`
nc_data <- nc_read(path = path_to_data,
                   protocol = path_to_protocol)
```

Tus datos ya están cargados en R y guardados en el objeto `nc_data`. `nc_data` es un objeto de tipo lista que contiene tres elementos que se usan con frecuencia para guardar datos de redes egocéntricas.

### Lista de egos {#ego-list}

El primero de estos elementos es un data frame llamado `egos`. Este data frame es una _lista de egos_ que contiene los datos de cada participante, o ego (la persona entrevistada), que ha completado el protocolo de Network Canvas. Cada fila de la lista de egos corresponde a un ego concreto, al que se asigna un número de identificación único. Estos números de identificación son distintos de los números de ID únicos del caso y de la sesión que asigna el software de Network Canvas; sin embargo, se corresponden exactamente entre sí y pueden usarse indistintamente, según prefieras.

La primera columna de la lista de álteres indica a qué ego está asociado cada álter; sus valores coinciden con los números de ID únicos que contiene `egos`. La segunda columna identifica al álter, y a cada álter también se le asigna un número de ID único dentro de cada red de ego.

La tercera columna indica el «tipo» de nodo asociado a cada álter, tal como se define en el protocolo de Network Canvas. Si los datos recopilados con un protocolo incluyen varios tipos de nodo para los álteres, `nc_read` convertirá `alters` en una lista de data frames. Cada data frame de esta lista es una lista de álteres de un tipo de nodo concreto y recibe el nombre de ese tipo de nodo.

Las columnas siguientes contienen más datos sobre cada álter o sobre la relación de un ego con ese álter. Una vez más, también tienes a tu disposición los números de ID creados por el propio Network Canvas.

### Listas de vínculos entre álteres {#alter-edgelists}

El último elemento que crea `nc_read`, `alter_edgelists`, contiene una o varias _listas de vínculos entre álteres_ en las que cada fila representa un vínculo que conecta entre sí a dos álteres de la red de un ego. No todos los protocolos de Network Canvas recopilan datos sobre los vínculos entre los álteres de la red de un ego. Por eso, `alter_edgelists` solo aparecerá en `nc_data` si tus datos recogen realmente vínculos entre álteres:

```r
# Observe names of data frames stored in `alter_edgelists`
names(nc_data$alter_edgelists)
```

```
## [1] "Close"   "DrugTie" "SexTie"
```

En nuestro ejemplo, vemos que `alter_edgelists` es una lista que contiene tres data frames llamados `Close`, `DrugTie` y `SexTie`. Esto se debe a que el protocolo de Network Canvas que generó nuestros datos registró tres «tipos» distintos de vínculos entre álteres. `nc_read` crea una lista de vínculos entre álteres independiente para cada tipo de vínculo, lo que facilita extraer solo los vínculos entre álteres que se necesitan para un fin concreto. Si nuestro protocolo de ejemplo hubiera recopilado varios tipos de nodo para los álteres, el elemento `alters` de `nc_data` tendría una organización similar.

La primera columna de cada uno de estos data frames representa al ego en cuya red aparece cada vínculo; sus valores coinciden con las columnas `ego_id` de nuestra lista de egos y de nuestra lista de álteres. La columna siguiente, `edge_id`, es un número de ID de cada vínculo dentro de la red. Las dos columnas siguientes contienen los números de ID de los álteres que conecta cada vínculo; sus valores coinciden con `alter_id` en la lista de álteres. Todas las demás columnas de `alter_edgelists` contienen atributos de la relación entre dos álteres de la red de un ego. Entre ellas se incluyen columnas con los ID originales de ego y de álter generados por el software de Network Canvas.

## Analizar los datos con egor {#analyzing-data-using-egor}

Con el paquete `nc_read` de `ideanet` has importado correctamente los datos de Network Canvas en R. Ahora puedes analizar y visualizar los datos como quieras.

Hay muchas herramientas y métodos para analizar datos de redes egocéntricas en R, entre ellas otras herramientas del propio paquete `ideanet`. Sin embargo, el resto de este tutorial se centra en analizar los datos con el paquete `egor`, que es el que nuestro equipo más ha usado con datos de Network Canvas. Además, los datos de `nc_read` tienen un formato que los hace fácilmente compatibles con `egor`. Los ejemplos de esta sección están adaptados de una [viñeta](https://cran.r-project.org/web/packages/egor/vignettes/using_egor.html) (en inglés) del propio paquete `egor`.

Para empezar con estos ejemplos, tendrás que instalar o cargar (o ambas cosas) los paquetes `egor`, `sna` y `ggplot2` en tu sesión de R:

```r
# Load required packages
library(egor)
library(sna)
library(ggplot2)
```

A continuación, tendremos que dividir la lista de álteres guardada en `nc_data` en data frames independientes para cada tipo distinto de vínculo entre ego y álter. Al igual que los vínculos entre álteres que aparecen en `alter_edgelists`, los vínculos entre egos y álteres también pueden ser de distintos tipos. Sin embargo, no se trata de los «tipos de nodo» que aparecen en la columna `node_type` de `alters`. En el caso de los vínculos entre ego y álter, solemos registrar los «tipos de vínculo» como un conjunto de variables `TRUE`/`FALSE` que indican la presencia de distintos tipos de relaciones dentro de un mismo par ego-álter. Cuando `egor` lee datos de redes egocéntricas, da por hecho que todos los vínculos entre egos y álteres son del mismo tipo. Dividir nuestra lista de álteres en data frames independientes garantiza que `egor` produzca medidas y visualizaciones precisas para cada tipo de vínculo entre ego y álter.

```r
# Create alter list for only "Close" ties
close_alters <- nc_data$alters %>% filter(Close == TRUE)

# Create alter list for only "Drugs" ties
drug_alters <- nc_data$alters %>% filter(Drugs == TRUE)

# Create alter list for only "Sex" ties
sex_alters <- nc_data$alters %>% filter(Sex == TRUE)
```

Según cómo se hayan registrado los distintos tipos de vínculos entre álteres en un protocolo de Network Canvas, puede que tengas que hacer algo parecido a lo anterior con `alter_edgelists` en `nc_data`. Sin embargo, las listas de vínculos entre álteres de nuestro `nc_data` de ejemplo coinciden con los tipos de vínculos guardados en cada uno de los data frames anteriores, así que basta con extraerlas de `nc_data` para continuar.

```r
# Create alter-alter edgelist for "Close" ties
close_aa <- nc_data$alter_edgelists$Close

# Create alter-alter edgelist for "Drugs" ties
drug_aa <- nc_data$alter_edgelists$DrugTie

# Create alter-alter edgelist for "Sex" ties
sex_aa <- nc_data$alter_edgelists$SexTie
```

### Crear un objeto egor {#creating-an-egor-object}

Una vez divididas por tipo de vínculo nuestra lista de álteres y nuestra lista de vínculos entre álteres, podemos empezar a crear los objetos de clase `egor` que `egor` usa para el análisis. Aunque hemos creado data frames para 3 tipos distintos de vínculos, nos centraremos en el conjunto completo de álteres de la red de cada ego y solo en los vínculos «Close» entre los álteres de cada red. Esto se debe a que la función `egor` exige que todos los nodos de la lista de vínculos entre álteres aparezcan en la lista de álteres, y la mejor forma de garantizarlo es incluir la lista de álteres completa:

```r
# Note that the `egor` function will also work if we specify the ID values
# in our data generated by Network Canvas
egorNetworkCanvas <- egor(
           # Note we are using the alter list specifically for "Close" ties
           alters = nc_data$alters,
           # Our ego list is unchanged, so we draw on it as it is stored in
           # `nc_data`
           egos = nc_data$egos,
           # We use `close_aa` as our alter-alter edgelist, which is the same
           # as `nc_data$alter_edgelists`
           aaties = close_aa,
           #
            ID.vars = list(
             ego = "networkCanvasEgoUUID",
             alter = "networkCanvasUUID",
             source = "networkCanvasSourceUUID",
             target = "networkCanvasTargetUUID"))
```

### Visualización de datos {#data-visualization}

Con nuestro objeto `egor` listo, empecemos con una visualización sencilla de una sola red de ego. Para ello, primero convertiremos esta red en un objeto `network` y usaremos la función `gplot` del paquete `sna`. Esta visualización muestra las nuevas etiquetas de los nodos y colorea cada nodo según la frecuencia de contacto con la persona participante. Además, disponemos la figura con las coordenadas finales de la etapa «Sociograma».

```r
oneEgoNet <- as_network(egorNetworkCanvas)[[1]]



oneEgoNet%v%"vertex.names" <- oneEgoNet%v%"name"

colorScheme <- c( "#CC6677", "#117733", "#AA4499",
                  "#6699CC")

# A little recoding to get a color for each frequency
nodeColors <- ifelse(oneEgoNet%v%"ContactFreq"=="Daily",colorScheme[1],
                    ifelse(oneEgoNet%v%"ContactFreq"=="Weekly",colorScheme[2],
                           ifelse(oneEgoNet%v%"ContactFreq"=="Less than \n weekly",colorScheme[3],
                                  colorScheme[4])))

gplot(oneEgoNet,
       usearrows = FALSE,
       label = oneEgoNet%v%"name",
       displaylabels = TRUE,
       vertex.col=nodeColors,
       edge.col="gray",
       coord = matrix(c(as.numeric(oneEgoNet%v%"Cords_x"),
                        -as.numeric(oneEgoNet%v%"Cords_y")),
                        nrow=length(unique(oneEgoNet%v%"name")),
                        ncol=2))
```

Como ves, esto solo muestra la red de un ego. Sin embargo, el paquete `egor` tiene varias funciones que facilitan la comparación de redes de varios egos, aunque puede que tengas que modificar un poco tus datos para garantizar la compatibilidad. Por ejemplo, así crearíamos una visualización que muestra cada red con la posición de los nodos en función de su frecuencia de contacto con la persona participante y de si consumen o no drogas con ella (es decir, `TRUE`/`FALSE`):

```r
# Make a visualization displaying both frequency of communication and drug use status

# A quick note: `egor`'s visualization tools don't appear to like working with `logical`-class
# vectors such as the `Drugs` variable in our alter list. To allow for smooth visualization,
# we recode `Drugs` as a new character variable with the labels we want to use in our visualization:
egorNetworkCanvas$alter$Drugs_label <- ifelse(is.na(egorNetworkCanvas$alter$Drugs), "Not Drug Partner", "Drug Partner")

# We'll also recode our `ContactFreq` variable to show better labels
egorNetworkCanvas$alter$ContactFreq_label <- ifelse(egorNetworkCanvas$alter$ContactFreq == "Less_than_weekly",
                                                    "Less than\nweekly",
                                                    egorNetworkCanvas$alter$ContactFreq)

# And we'll want to create a label column for node IDs as well
egorNetworkCanvas$alter$alter_label <- as.character(egorNetworkCanvas$alter$.altID)

plot(egorNetworkCanvas,
     venn_var = "Drugs_label",
     pie_var = "ContactFreq_label",
     vertex_label_var = "name",
     type = "egogram")
```

También podemos usar un paquete tradicional, como `sna`, para examinar estas redes aplicando funciones (es decir, `lapply`) a cada una de ellas y agregando los resultados. Por ejemplo, aquí primero creamos un histograma sencillo de los grados de los álteres en todas las redes de ego.

```r
networkNetworkCanvas <- as_network(egorNetworkCanvas)

histData <- networkNetworkCanvas %>%
  lapply(degree,cmode="indegree") %>%
  unlist(recursive = FALSE) %>%
  as.data.frame()

histData$degree <- as.numeric(histData$".")

ggplot(histData, aes(x=degree)) +
    geom_histogram(color="black", fill="white",bins=5) +
    theme_classic()
```

Por último, a menudo queremos examinar cómo un atributo del ego puede estar asociado a las características de su red. En este ejemplo, observamos la asociación entre el consumo de marihuana declarado por cada participante y la densidad de su red de ego.

```r
ego_density(egorNetworkCanvas) %>%
  full_join(egorNetworkCanvas$ego,by=".egoID") %>%
  ggplot(aes(x = MarijuanaUsed, y = density)) +
    geom_point(size=5) +
    geom_text(label=egorNetworkCanvas$ego$networkCanvasCaseID, aes(vjust=c(-1.5),
                                                                   hjust=c(-.5))) +
    ylim(0,1.05) + theme_classic()
```
