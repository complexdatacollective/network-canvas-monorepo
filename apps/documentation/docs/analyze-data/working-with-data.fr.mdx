## Introduction {#introduction}

Ce tutoriel présente un exemple de flux de travail d’importation et d’analyse de données [Network Canvas](https://networkcanvas.com/fr/) dans l’environnement statistique R, à l’aide des packages [ideanet](https://cran.r-project.org/web/packages/ideanet/index.html) (en anglais) et [egor](https://cran.r-project.org/web/packages/egor/index.html) (en anglais). Cet exemple utilise des données simulées à partir du [fichier de protocole Network Canvas](https://github.com/complexdatacollective/working-with-data/raw/main/IJE_RADAR_Protocol.netcanvas) suivant, qui peut être ouvert dans les applications Interviewer ou Architect. Si vous suivez cet exemple avec votre propre protocole, vous devrez d’abord exporter les données recueillies avec celui-ci. Nous ne décrivons pas ici la procédure d’exportation, mais nous vous invitons à consulter le [guide d’exportation des données](/fr/analyze-data/data-export) et la page [Flux de travail des protocoles et des données](/fr/collect-data/protocol-and-data-workflows) pour plus de détails. Notez que, pour ce flux de travail, vous devrez exporter vos données avec l’option CSV et non avec l’option GraphML.

Si vous n’utilisez pas votre propre protocole, vous pouvez télécharger [ici](https://github.com/complexdatacollective/working-with-data/raw/main/networkCanvasExport.zip) les fichiers CSV utilisés dans ce tutoriel. Le téléchargement du fichier de protocole indiqué plus haut est facultatif, mais nous vous recommandons vivement de le télécharger lui aussi. Le flux de travail de ce tutoriel s’appuie sur des outils capables de lire les fichiers de protocole Network Canvas et d’exploiter les informations qu’ils contiennent pour traiter les données plus efficacement.

Si vous avez besoin de ressources supplémentaires, ou par simple curiosité, vous trouverez [ici](https://github.com/complexdatacollective/working-with-data) (en anglais) un dépôt GitHub complet consacré à ce tutoriel.

## Localiser vos données {#locating-your-data}

Si vous avez téléchargé nos données d’exemple ou exporté avec succès vos propres données, vous devriez maintenant disposer, quelque part sur votre ordinateur, d’un dossier de fichiers CSV Network Canvas. Le contenu de ce dossier devrait ressembler à la capture d’écran ci-dessous (notez que le début de chaque nom de fichier sera probablement différent si vous travaillez avec vos propres données) :

<ImageFullWidth src="/assets/img/working-with-data/nc_directory_list.png" alt="Un dossier de fichiers CSV exportés depuis Network Canvas"></ImageFullWidth>

Une fois vos données en main, la première chose à faire dans R est de créer un objet qui enregistre le chemin de ce dossier sous forme de chaîne de caractères.

```r
# Store path to folder with Network Canvas data
### Note that this path will almost certainly be different on your own computer
path_to_data <- paste0(getwd(),'/networkCanvasExport/')
```

Si vous comptez utiliser votre fichier de protocole Network Canvas, comme nous l’avons recommandé plus haut, enregistrez également le chemin du fichier de protocole dans un autre objet.

```r
# Store path to Network Canvas protocol file
### Note that this path will almost certainly be different on your own computer
path_to_protocol <- paste0(getwd(),'/IJE_RADAR_Protocol.netcanvas')
```

## Lire les données avec ideanet {#reading-data-using-ideanet}

Une fois ces chemins définis, utilisez le package [`ideanet`](https://cran.r-project.org/web/packages/ideanet/index.html) (en anglais) pour charger vos données dans R. Le package `ideanet` propose une fonction spécialement conçue pour lire les données recueillies avec Network Canvas, nommée `nc_read`. `nc_read` prend un argument principal, `path`, une chaîne de caractères indiquant le dossier qui contient les fichiers CSV Network Canvas à traiter. Si vous disposez aussi du fichier de protocole Network Canvas utilisé pour recueillir vos données, vous pouvez indiquer son emplacement à `nc_read` au moyen de l’argument `protocol`. Bien que facultatif, cet argument permet à `nc_read` d’accéder aux informations contenues dans votre fichier de protocole, ce qui assure un meilleur codage des variables catégorielles de vos données. De manière générale, il est recommandé d’utiliser votre fichier de protocole avec `nc_read` si vous en disposez.

Notez que vous avez déjà indiqué l’emplacement des données (`path_to_data`) et celui du fichier de protocole (`path_to_protocol`), ce qui permet de passer facilement à `nc_read` :

```r
# Load `ideanet`
library(ideanet)

# Set up `nc_read`
nc_data <- nc_read(path = path_to_data,
                   protocol = path_to_protocol)
```

Vos données sont maintenant chargées dans R et enregistrées dans l’objet `nc_data`. `nc_data` est un objet de type liste qui contient trois éléments couramment utilisés pour stocker des données de réseaux égocentrés.

### Liste des egos {#ego-list}

Le premier de ces éléments est un data frame (tableau de données R) nommé `egos`. Ce data frame est une _liste des egos_ qui contient les données relatives à chaque personne participante, ou ego (la personne au centre de son réseau), ayant répondu à l’ensemble du protocole Network Canvas. Chaque ligne de la liste des egos correspond à un ego donné, auquel est attribué un numéro d’identification unique. Ces numéros d’identification sont distincts des identifiants uniques de cas et de session attribués par le logiciel Network Canvas ; chaque numéro correspond toutefois exactement à un identifiant de cas et à un identifiant de session, de sorte que vous pouvez utiliser indifféremment ces numéros ou les identifiants Network Canvas, selon votre préférence.

La première colonne de la liste des alters indique l’ego auquel un alter donné est associé ; ses valeurs correspondent aux numéros d’identification uniques contenus dans `egos`. La deuxième colonne identifie l’alter concerné ; les alters reçoivent eux aussi un numéro d’identification unique au sein de chaque réseau personnel.

La troisième colonne indique le « type » de nœud associé à chaque alter, tel qu’il est défini dans le protocole Network Canvas. Si les données recueillies par un protocole comportent plusieurs types de nœuds pour les alters, `nc_read` fera de `alters` une liste de data frames. Chaque data frame de cette liste est une liste des alters d’un type de nœud donné et porte le nom de ce type de nœud.

Les colonnes suivantes contiennent d’autres données relatives à chaque alter ou à la relation d’un ego avec cet alter. Là encore, les numéros d’identification créés par Network Canvas lui-même restent disponibles.

### Listes des liens entre alters {#alter-edgelists}

Le dernier élément créé par `nc_read`, `alter_edgelists`, contient une ou plusieurs _listes des liens entre alters_, dans lesquelles chaque ligne représente un lien qui relie deux alters du réseau d’un ego. Tous les protocoles Network Canvas ne recueillent pas de données sur les liens entre les alters du réseau d’un ego. Par conséquent, `alter_edgelists` n’apparaîtra dans `nc_data` que si vos données comportent effectivement des liens entre alters :

```r
# Observe names of data frames stored in `alter_edgelists`
names(nc_data$alter_edgelists)
```

```
## [1] "Close"   "DrugTie" "SexTie"
```

Dans notre exemple, nous constatons que `alter_edgelists` est une liste qui contient trois data frames nommés `Close`, `DrugTie` et `SexTie`. En effet, le protocole Network Canvas qui a produit nos données a enregistré trois « types » différents de liens entre alters. `nc_read` crée une liste des liens entre alters distincte pour chaque type de lien, ce qui permet d’extraire plus facilement les seuls liens entre alters dont vous avez besoin pour un usage donné. Si notre protocole d’exemple avait recueilli plusieurs types de nœuds pour les alters, l’élément `alters` de `nc_data` serait organisé de la même manière.

La colonne suivante, `edge_id`, est le numéro d’identification d’un lien donné au sein du réseau. Les deux colonnes suivantes contiennent les numéros d’identification des alters que relie un lien donné ; leurs valeurs correspondent à `alter_id` dans la liste des alters. La colonne qui suit, `edge_type`, indique le type de lien qui relie deux alters dans un réseau. Toutes les autres colonnes de `alter_edgelists` contiennent des attributs de la relation entre deux alters du réseau d’un ego, dont des colonnes contenant les identifiants d’origine des egos et des alters générés par le logiciel Network Canvas.

## Analyser les données avec egor {#analyzing-data-using-egor}

Grâce à la fonction `nc_read` de `ideanet`, vous avez importé avec succès les données Network Canvas dans R. Vous pouvez maintenant analyser et visualiser les données comme vous le souhaitez.

De nombreux outils et méthodes permettent d’analyser des données de réseaux égocentrés dans R, dont d’autres outils du package `ideanet`. La suite de ce tutoriel se concentre toutefois sur l’analyse des données avec le package `egor`, celui que notre équipe a le plus utilisé avec des données Network Canvas. En outre, les données produites par `nc_read` sont mises en forme pour être facilement compatibles avec `egor`. Les exemples présentés ici sont adaptés d’une [vignette](https://cran.r-project.org/web/packages/egor/vignettes/using_egor.html) (en anglais) du package `egor` lui-même.

Pour commencer ces exemples, vous devrez installer et/ou charger les packages `egor`, `sna` et `ggplot2` dans votre session R :

```r
# Load required packages
library(egor)
library(sna)
library(ggplot2)
```

Le chargement de `egor` attache aussi le package `dplyr`, qui fournit le pipe `%>%` ainsi que les fonctions `filter()` et `full_join()` utilisées dans la suite de ce tutoriel.

Nous devons ensuite diviser la liste des alters enregistrée dans `nc_data` en data frames distincts, un pour chaque type de lien ego-alter. Tout comme les liens entre alters qui figurent dans `alter_edgelists`, les liens entre les egos et les alters peuvent eux aussi être de différents types. Il ne s’agit cependant pas des « types de nœuds » qui figurent dans la colonne `node_type` de `alters`. Pour les liens ego-alter, nous enregistrons généralement les « types de liens » sous la forme d’un ensemble de variables `TRUE`/`FALSE` qui indiquent la présence de différents types de relations au sein d’une même paire ego-alter. Lorsque `egor` lit des données de réseaux égocentrés, il suppose que tous les liens entre les egos et les alters sont du même type. Diviser notre liste des alters en data frames distincts garantit que `egor` produira des mesures et des visualisations exactes pour chaque type de lien ego-alter.

```r
# Create alter list for only "Close" ties
close_alters <- nc_data$alters %>% filter(Close == TRUE)

# Create alter list for only "Drugs" ties
drug_alters <- nc_data$alters %>% filter(Drugs == TRUE)

# Create alter list for only "Sex" ties
sex_alters <- nc_data$alters %>% filter(Sex == TRUE)
```

Selon la manière dont les différents types de liens entre alters ont été enregistrés dans un protocole Network Canvas, vous devrez peut-être procéder de la même façon pour `alter_edgelists` dans `nc_data`. Dans notre exemple, cependant, les listes des liens entre alters de `nc_data` correspondent aux types de liens stockés dans chacun des data frames ci-dessus : il suffit donc de les extraire de `nc_data` pour continuer.

```r
# Create alter-alter edgelist for "Close" ties
close_aa <- nc_data$alter_edgelists$Close

# Create alter-alter edgelist for "Drugs" ties
drug_aa <- nc_data$alter_edgelists$DrugTie

# Create alter-alter edgelist for "Sex" ties
sex_aa <- nc_data$alter_edgelists$SexTie
```

### Créer un objet egor {#creating-an-egor-object}

Une fois notre liste des alters et notre liste des liens entre alters divisées par type de lien, nous pouvons commencer à créer les objets de classe `egor` qu’utilise `egor` pour l’analyse. Bien que nous ayons créé des data frames pour trois types de liens différents, nous nous concentrerons sur l’ensemble des alters du réseau de chaque ego et uniquement sur les liens « Close » (relations proches) entre les alters de chaque réseau. En effet, la fonction `egor` exige que tous les nœuds de la liste des liens entre alters figurent dans la liste des alters, et inclure la liste complète des alters est le meilleur moyen de s’en assurer :

```r
# Note that the `egor` function will also work if we specify the ID values
# in our data generated by Network Canvas
egorNetworkCanvas <- egor(
           # Note we are using the full alter list, so that every alter in
           # `close_aa` also appears in it
           alters = nc_data$alters,
           # Our ego list is unchanged, so we draw on it as it is stored in
           # `nc_data`
           egos = nc_data$egos,
           # We use `close_aa` as our alter-alter edgelist, which is the same
           # as `nc_data$alter_edgelists$Close`
           aaties = close_aa,
           #
            ID.vars = list(
             ego = "networkCanvasEgoUUID",
             alter = "networkCanvasUUID",
             source = "networkCanvasSourceUUID",
             target = "networkCanvasTargetUUID"))
```

### Visualisation des données {#data-visualization}

Une fois notre objet `egor` en main, commençons par une visualisation simple d’un seul réseau personnel. Pour cela, nous convertissons d’abord ce réseau en objet `network`, puis nous utilisons la fonction `gplot` du package `sna`. Cette visualisation affiche les nouveaux libellés des nœuds et colore chaque nœud selon la fréquence des contacts avec la personne participante. Nous plaçons également les nœuds selon les coordonnées finales enregistrées à l’étape « Sociogramme ».

```r
oneEgoNet <- as_network(egorNetworkCanvas)[[1]]
```

```r
# we recode `Drugs` as a new character variable with the labels we want to use in our visualization:
egorNetworkCanvas$alter$Drugs_label <- ifelse(is.na(egorNetworkCanvas$alter$Drugs), "Not Drug Partner", "Drug Partner")

# We'll also recode our `ContactFreq` variable to show better labels
egorNetworkCanvas$alter$ContactFreq_label <- ifelse(egorNetworkCanvas$alter$ContactFreq == "Less_than_weekly",

                                                    egorNetworkCanvas$alter$ContactFreq)

egorNetworkCanvas$alter$alter_label <- as.character(egorNetworkCanvas$alter$.altID)

plot(egorNetworkCanvas,
     venn_var = "Drugs_label",
     pie_var = "ContactFreq_label",
     vertex_label_var = "name",
     type = "egogram")
```

Nous pouvons aussi utiliser un package classique, comme `sna`, pour examiner ces réseaux en appliquant des fonctions à chacun d’eux (au moyen de `lapply`) et en agrégeant les résultats. Ici, par exemple, nous créons d’abord un histogramme simple des degrés des alters sur l’ensemble des réseaux personnels.

```r
networkNetworkCanvas <- as_network(egorNetworkCanvas)

histData <- networkNetworkCanvas %>%
  lapply(degree,cmode="indegree") %>%
  unlist(recursive = FALSE) %>%
  as.data.frame()

histData$degree <- as.numeric(histData$".")

ggplot(histData, aes(x=degree)) +
    geom_histogram(color="black", fill="white",bins=5) +
    theme_classic()
```
