<Definition>
  A dynamic value is information that the interview fills into your text as
  the participant reads it, such as the participant's name, an answer they
  gave earlier, or today's date.
</Definition>

Dynamic values let your text speak to the participant about their own answers. Instead of "How often do you talk to this person?", a question can say "How often do you talk to Sam?". Instead of "In the last month, who have you asked for advice?", it can name the date the participant takes the interview.

Values come from the interview's own data. Showing them in your text doesn't store or send them anywhere else.

<TipBox>

Dynamic values need [schema 9](/en/get-started/protocol-schema-information#schema-version-9). Build your protocol in Architect, and run it in Fresco 5.0 or later, or Interviewer 9.0 or later.

</TipBox>

## What a value can be

A value is one of these:

- **Today's date.** This is the only fact about the interview itself that text can show. It is the date on the day the participant reads the text.
- **An attribute of the participant**, such as a name or an answer from an Ego Form.
- **The label of a node that the text is about**, on stages and forms that ask about one node or two nodes at a time. This is the text the interview shows on the node, so a question on a Dyad Census can ask "Are Jim and Alice friends?" with the same names the participant sees on the two nodes. See [A node's label](#a-nodes-label).
- **An attribute of the node or edge that the text is about**, on the same stages and forms. For example, an Alter Form question can ask "Did you study at Northwestern?", filling in the university the participant named for that node on an earlier stage.

These kinds of attribute can be shown: text, number, scalar, date, boolean (yes or no), ordinal and categorical. Encrypted attributes are never offered, and neither are layout or location attributes.

Which values a text can show depends on where it sits. See [What each kind of text can show](#what-each-kind-of-text-can-show).

## Inserting a value

Every text that can show values has a syringe button in its toolbar. Point at it to see its name, **Inject piped text from interview metadata or a network attribute**. To insert a value:

1. Click in the text where the value should go.
2. Click the syringe button, or type `{`.
3. A menu lists the values this text can show. Type to search it.
4. Choose a value with a click, or press Enter to choose the highlighted one.

The menu groups values under headings:

- **Interview Attributes**, for today's date
- **Ego Attributes**, for the participant's attributes
- **Contextual Attributes**, for the label and attributes of whatever the text is shown with: the node or edge a form asks about, or the node a question asks about. Each node there is offered first as **Node label**. On a Dyad Census or Tie-Strength Census there are two of these headings, **Contextual Attributes: First Node in Pair** and **Contextual Attributes: Second Node in Pair** (see [What each kind of text can show](#what-each-kind-of-text-can-show))

Under each value, the menu says what kind of attribute it is.

To type a brace as an ordinary character, press Escape after typing `{`. The menu closes and the brace stays in your text.

In the text, a value appears as a pill that starts with the syringe icon and is named after its attribute, such as **nickname**. On a Dyad Census or Tie-Strength Census, a value of one of the two nodes also says which node it belongs to, such as **nickname (first node in pair)**. A node's label appears as **Node label**, or with the node it belongs to, such as **Node label (first node in pair)**. Today's date appears as **Today's date**. The same pills appear in the [translation table](/en/design-protocols/translating-your-protocol#the-translation-table) and on the protocol's **Summary** tab.

Architect keeps track of the values each stage's text shows. An attribute that some text shows counts as in use in the [codebook](/en/design-protocols/key-concepts/codebook), so you can't delete it until you remove it from that text.

## When a value is missing

Any attribute can be missing when the participant reaches your text. The participant may have skipped the question, [skip logic](/en/design-protocols/key-concepts/skip-logic) may have skipped the stage that asks it, or data imported from a roster may not include it. Going back and changing answers, or deleting a node, can also leave an attribute unset, even when your protocol normally asks for it first.

So that the participant never meets a gap, a value that can be missing goes in with two versions of the text around it:

- **If known**, which shows the value. This is what the participant sees when the value is there.
- **If not known**, which is shown instead when the value is missing.

Architect adds both versions for you when you insert a value. Write the words that fit each case in each version. A version can be left empty, so that nothing is shown in that case. An empty version reads **Shows nothing** in the editor; the participant sees nothing there.

In the editor, a value with versions shows only as its pill until you select it. Click the pill, or reach it with the arrow keys and press Enter or Space, to open its versions; press Escape, or leave the text, to fold it back into the pill. A value you have just inserted starts open, so that you can write its versions straight away. Everywhere else, such as the list of form fields, the field preview and the protocol's **Summary** tab, the value shows only as its pill.

For example, an Ego Form's title could thank the participant by name:

| Version      | You write                       | The participant sees |
| ------------ | ------------------------------- | -------------------- |
| If known     | ", " then the **nickname** pill | Thanks, Sam!         |
| If not known | nothing                         | Thanks!              |

Here the text "Thanks" comes before the versions and "!" after them, so both cases share them.

Zero and "no" are real answers, not missing ones: a number that is 0, or a yes-or-no answer of no, shows the **If known** version. Empty text, and a categorical answer with no options chosen, count as missing.

Today's date and a node's label are never missing, so they go in on their own, without versions.

## A node's label

A node's label is not one attribute. The interview chooses it for each node from that node's answers: an attribute called "name", then one whose name contains "name", then the first text attribute that has an answer. A node with none of these shows its node type's label. The label value follows the same rules, so it always shows the text on the node, even when two nodes of the same type take their labels from different attributes. When the label comes from an encrypted attribute, the text shows it exactly as the node does.

Use the label to name a node in a question, as in "Are Jim and Alice friends?". Use an attribute when the text needs that particular answer, such as a nickname, even if the label shows something else.

## Different wording for each answer

A categorical, ordinal or boolean attribute is listed twice in the syringe button's menu. The second entry is marked **Different wording for each answer**. Choose it to give the text one version for each answer, instead of showing the answer itself.

The versions are:

- **If not known**, for when there is no answer
- one version for each of the attribute's options, named by its label. A boolean attribute without labels of its own has **Yes** and **No**.
- **Any other answer**, for an answer that has no version of its own

For example, a question on a Per Alter Form could use a "Lives with you" attribute:

| Version          | You write                                   |
| ---------------- | ------------------------------------------- |
| If not known     | How often do you see them at home?          |
| Yes              | How do you share household tasks with them? |
| No               | How often do you visit them at home?        |
| Any other answer | (left empty, because yes and no cover it)   |

A categorical answer can include several options. The text then uses the version of the first of those options, in the order the attribute lists its options, or **Any other answer** if none of them has a version.

## Wording that fits the number

A number or scalar attribute is also listed twice in the syringe button's menu. The second entry is marked **Wording that fits the number**. Choose it when the words around the number change with it, as in "1 child" and "3 children".

It inserts **If known** and **If not known** versions, as for any value. Inside **If known**, there is one version for each form your language gives words for numbers, named with examples of the numbers it is used for. In English there are two:

| Version               | You write              | The participant sees |
| --------------------- | ---------------------- | -------------------- |
| When it is 1          | the number, "child"    | 1 child              |
| When it is 0, 2, 3, … | the number, "children" | 3 children           |

Each of these versions starts with the number. Type the words that go with it.

Other languages have a different number of forms: Chinese has one, and Polish and Russian have more than two. When you write the text in another language, Architect gives you that language's versions.

## What participants see

The interview shows each value in the participant's language:

- a date as their language writes dates. A date answer of only a month or a year shows only the month or year.
- a number as their language writes numbers
- an answer to a categorical, ordinal or boolean question by the option's label, in their language. An answer with several options is shown as a list, such as "cats, dogs and fish". A yes-or-no answer can be shown this way only when both of its answers have labels; otherwise, use **Different wording for each answer**.
- text exactly as it was entered

Each value is tinted with the interview's primary colour, so the participant can tell it was filled in for them. Screen readers announce it as a dynamic value, followed by the value.

## What each kind of text can show

Today's date can be shown in every text that accepts values. Which attributes a text can show depends on where it sits:

| Where the text sits                                                                                                                                                                                                                                                                                                           | Ego Attributes | Contextual Attributes                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Stage text: an Information stage's title and text, an Anonymisation stage's title and text, a Finish Screen's heading and text, an Ego Form's title, the panel titles of a name generator, and the panel title of a roster                                                                                                    | Yes            | None                                                                                                                                     |
| Prompts on the Name Generator, Quick Add, Roster, Sociogram, Ordinal Bin, Categorical Bin (including the label of its "other" bin) and Family Pedigree                                                                                                                                                                        | Yes            | None, because these stages show many nodes at once                                                                                       |
| Prompts on the Geospatial stage                                                                                                                                                                                                                                                                                               | Yes            | The label and every attribute of the node being placed                                                                                   |
| Prompts on the Dyad Census and Tie-Strength Census, and the Tie-Strength Census's label for the option that says no tie is present                                                                                                                                                                                            | Yes            | The label and every attribute of each of the two nodes the question asks about, under **First Node in Pair** and **Second Node in Pair** |
| Prompts on the One-to-Many Dyad Census                                                                                                                                                                                                                                                                                        | Yes            | The label and every attribute of the one node the participant links others to                                                            |
| An Ego Form's questions and hints                                                                                                                                                                                                                                                                                             | Yes            | None                                                                                                                                     |
| The questions and hints of forms about a node: Per Alter Form, Name Generator and Family Pedigree forms, and a Network Composer's fields for nodes, including each field's label and the labels at each end of its slider. The question a Categorical Bin asks about a node placed in its "other" bin counts as one of these. | Yes            | The label and every attribute of the node the form asks about                                                                            |
| A Per Alter Edge Form's questions and hints                                                                                                                                                                                                                                                                                   | Yes            | Every attribute of the edge the form asks about, and the labels of the two nodes it joins                                                |
| A Network Composer's fields for edges                                                                                                                                                                                                                                                                                         | Yes            | The labels of the two nodes the edge joins                                                                                               |

A form field can show any attribute of the node or edge its form asks about, including attributes collected on earlier stages and the attribute the field itself asks for. When the attribute has no value yet, the field shows the value's **If not known** version. A node's label in a form follows the answers as the participant types them, as the node does.

On an edge form, the two nodes' labels say which end they belong to: **Node label (first node of edge)** and **Node label (second node of edge)**. Their attributes aren't offered, because the nodes at either end of an edge can be of any type.

Some text never shows values:

- stage names
- image descriptions, because they stand in for an image
- text in the codebook, such as the labels of node types, edge types and options
- the [words Network Canvas supplies](/en/design-protocols/translating-your-protocol#words-network-canvas-supplies): stage wording and interview text

In a protocol upgraded from schema 8, braces that were already in your text stay as ordinary characters. They never become values.

## Translating text that shows values

When your protocol has more than one language (see [Translating Your Protocol](/en/design-protocols/translating-your-protocol)), each language writes its own versions of the text. A translation must show every value wherever the default language's text shows it, in each version. For example, if the English **If known** version shows the **nickname** pill, the **If known** version of each translation must show it too.

There is one exception. A version for a word form that only one number takes may leave the number out, because the words already say which number it is. A number answer can be negative, so in practice this is a form for zero alone, which some languages have. English "1 child" doesn't count, because English uses the same form for -1.

In the translation table, a cell shows values, and each set of versions, as pills. When you edit a cell, select a pill to open its versions, as in the stage editor. When you edit a cell, the syringe button offers the values the stage already shows. To show a new value, add it in the stage editor first.

When a translation leaves out a value, the cell says so, such as "Include “nickname” wherever the original text shows it.", and the table won't save until you fix it. If a text chooses between so many versions that its translation can't be checked, the cell asks you to use fewer values that change the wording.

You don't translate the values themselves. Dates and numbers follow the participant's language, and answers are shown with their options' labels in that language.

## Problems Architect reports

Protocol validation checks every text that shows values. Each of these is an error, and your protocol isn't valid until you fix it:

- **A value can't be shown here.** The text shows a value that isn't available where it sits (see [What each kind of text can show](#what-each-kind-of-text-can-show)). This can happen when the attribute it shows no longer exists or has been made encrypted.
- **A value can be missing, so the text needs a version for when it is missing.** The text shows an attribute outside an **If known** version. Every attribute can be missing, so the text needs an **If not known** version for it (see [When a value is missing](#when-a-value-is-missing)).
- **A version stands for an answer the attribute doesn't have.** This happens when you remove or change one of an attribute's options after giving text a version for each of its answers. Remove every set of versions for that attribute from the stage's text, then insert them again, so that they match the attribute's options.
- **A translation must show a value where the default language's text does.** See [Translating text that shows values](#translating-text-that-shows-values).
- **Too many versions to check a translation.** Use fewer values that change the wording in that text.
- **A yes-or-no attribute needs labels for both of its answers.** The text shows the answer itself, but the attribute has no labels for yes and no. Add both labels to the attribute, or give the text **Different wording for each answer**.
- **Text can't be blank in every version.** At least one version must show some text or a value.
