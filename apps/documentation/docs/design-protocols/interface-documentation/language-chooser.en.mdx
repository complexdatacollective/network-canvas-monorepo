The Language Chooser interface is a screen where participants choose the language for the rest of the interview, from the languages your protocol is written in. It is useful whenever your protocol has more than one language, and you can't be sure that a participant's device or browser is set to the language they want to use.

To set up the languages a participant can choose from, see [Translating Your Protocol](/en/design-protocols/translating-your-protocol). You can also add and remove languages in this stage's editor (see [Configuring the Language Chooser](#configuring-the-language-chooser)).

## What participants see

The screen has the heading "Choose a language", followed by a list of languages. Network Canvas writes the heading itself, in the same language as the interview's buttons and messages.

The list contains exactly the languages your protocol is written in, in alphabetical order for the language of the interview's own buttons and messages. Each language is written in its own language and script, so a Spanish speaker sees **Español** and a Japanese speaker sees **日本語**, whatever language the screen is currently in. Languages have no other order: the order your protocol stores them in makes no difference.

The language the interview is currently shown in is already selected. When the participant picks another one, the change happens straight away: the heading and the interview's own buttons and messages switch to that language, and so does every later screen of the interview. The participant can change their mind as often as they like before moving on. A text with no translation in the language they pick appears in another of your protocol's languages (see [The default language and which translation participants see](/en/design-protocols/translating-your-protocol#the-default-language-and-which-translation-participants-see)).

The participant can always move on to the next screen, even if they don't pick a language. If they leave the selected language as it is, the interview keeps choosing its language from the language settings of their device or browser, as it did before this screen. Once they pick a language, the interview keeps it, including when the interview is resumed later.

The interview's own buttons and messages are available in a fixed set of languages. If the participant picks a language that Network Canvas doesn't have, your protocol's text is shown in that language, and the buttons and messages are shown in a language from the participant's device or browser settings if Network Canvas has one, or otherwise in English.

## Configuring the Language Chooser

The stage editor has these sections:

- **Languages** lists the languages participants can choose from: every language your protocol is written in, in alphabetical order. You can manage them right here. It is the same list as on Architect's **Languages** page, with the same rules (see [Managing your protocol's languages](/en/design-protocols/translating-your-protocol#managing-your-protocols-languages)), so a change made in one place appears in the other. A change also applies to this stage's changes that you haven't saved yet. You can:
  - add languages with **Add languages**. A new language starts with no translations.
  - choose the default language from the **Default language** list, once your protocol has more than one language.
  - stop offering a language with the delete button at the end of its row, which deletes its translations. You can't remove the default language until another language is the default. You can't remove a language that holds the only translation of some text until that text is translated into another language. This includes text on this stage that you haven't saved yet. When you can't remove a language, its delete button is unavailable. Point to it, or move to it with the keyboard, to see why.
  - open [the translation table](/en/design-protocols/translating-your-protocol#the-translation-table) with **Open translation table**. A **Missing translations** badge marks each language that some texts aren't translated into yet. The table opens over the **Languages** tab, so if this stage has changes you haven't saved, Architect asks whether to discard them first.
- [Skip logic](/en/design-protocols/key-concepts/skip-logic) and interviewer guidance work as they do on other stages.

## Data

The Language Chooser does not create nodes or edges, and it doesn't add anything to the participant's network. The language the interview was shown in is recorded with each interview and included in your exported data. See [Interview language](/en/analyze-data/data-export#interview-language).

### Best Practices

<GoodPractice>

Put the Language Chooser at the very start of your protocol, before any screen with text that participants need to understand.

</GoodPractice>

<GoodPractice>

Translate every text of your protocol into each of its languages before you start collecting data. The translation table shows anything that is still missing (see [Finding missing translations](/en/design-protocols/translating-your-protocol#finding-missing-translations)).

</GoodPractice>

### Try to Avoid

<BadPractice>

Avoid adding a Language Chooser to a protocol that has only one language. Participants will see a single language to choose, which adds a step without giving them a choice.

</BadPractice>

<BadPractice>

Avoid relying on the participant's device to pick the right language when it matters for your study. Devices shared between people, or set up by someone else, may be set to a language the participant doesn't read.

</BadPractice>
