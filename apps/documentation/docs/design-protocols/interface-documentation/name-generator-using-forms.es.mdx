Los generadores de nombres son uno de los componentes fundamentales de una entrevista de redes. Permiten a la persona participante crear álteres (cada persona a la que se nombra durante la entrevista) y describir así una de las dos entidades principales de las redes de tu estudio.

Network Canvas incluye varias [interfaces](../key-concepts/interfaces) de generador de nombres que puedes añadir a tu estudio, y todas se pueden configurar en Architect.

![Interfaces de generador de nombres disponibles en Architect](/assets/img/interface-documentation/name-generators/add-screen.png)

Cada una de estas interfaces está pensada para una forma concreta de obtener álteres, con sus propias ventajas e inconvenientes. Aunque tienen algunas opciones de configuración [comunes a todas las demás interfaces de Network Canvas](./shared), este artículo se centra en las opciones propias de la interfaz principal de generador de nombres y de una variante suya que usa un modo de «adición rápida».

<TipBox>

¿Usas datos de una lista predefinida (una lista que se importa como archivo de datos) en tu estudio? Consulta nuestra documentación sobre la interfaz [«Generador
de nombres a partir de una lista»](./name-generator-roster).

</TipBox>

## Elementos comunes de las interfaces {#shared-interface-elements}

Las interfaces «Generador de nombres (con formularios)» y «Generador de nombres (adición rápida)» comparten algunos elementos visuales.

![](/assets/img/interface-documentation/name-generators/preview.png)

Son el área de la **pregunta**, donde se explica la tarea a la persona participante (consulta [Preguntas](/es/design-protocols/key-concepts/prompts)); un área de **lista de nodos**, donde se muestran los álteres que se han obtenido; un **botón de acción principal**, que inicia el proceso de obtención de nodos, y, de forma opcional, uno o varios [paneles laterales](#side-panels).

Además, puedes elegir cómo se crean exactamente los álteres: con un formulario completo o con un método sencillo de «adición rápida».

### Paneles laterales {#side-panels}

Los dos generadores de nombres pueden usar paneles laterales. Los paneles laterales son una función muy útil que permite usar datos de red, ya sea de la entrevista en curso o de un archivo de datos de red subido a la biblioteca de recursos de Architect, como apoyo para las tareas de generación de nombres.

Por ejemplo, cuando varias preguntas de un generador de nombres pueden solaparse en la red social de una persona participante, puede ser útil mostrar en una pantalla posterior los nodos nombrados anteriormente, para que la persona participante pueda volver a incluirlos fácilmente.

![Configurar un panel lateral](/assets/img/interface-documentation/name-generators/side-panel.png)

También se puede crear un panel lateral a partir de un archivo de datos de red (por ejemplo, una lista predefinida) para que la persona participante pueda seleccionar y nombrar álteres de una lista ya establecida. Es importante tener en cuenta que en los paneles laterales posteriores del generador de nombres aparecerá exactamente la misma lista, salvo que se creen una o varias reglas para filtrar los datos que se muestran en el panel (consulta [Filtrado de la red](../key-concepts/network-filtering)).

Durante la entrevista, los paneles laterales se pueden desplegar o contraer haciendo clic en su encabezado.

## Usar formularios {#using-forms}

Con la interfaz «Generador de nombres (con formularios)», el botón de acción principal abre un formulario que quienes participan tienen que completar para crear un álter. Este formulario puede incluir uno o varios campos para recoger datos de atributos concretos de cada nodo (consulta nuestro [artículo de conceptos clave sobre los formularios](../key-concepts/forms) para obtener más información sobre cómo crear un formulario). Así, esta interfaz combina la generación de álteres con la posibilidad de realizar algunas tareas básicas de recogida de atributos, o de interpretación de nombres.

![Un formulario de ejemplo](/assets/img/interface-documentation/name-generators/ng-form.png)

### Personalizar la redacción predeterminada {#customize-built-in-wording}

La sección **Personalizar la redacción predeterminada** del editor de la etapa contiene las palabras que leen quienes participan en esta etapa. Cada una empieza con la redacción de Network Canvas, en todos los idiomas para los que Network Canvas la tiene, y puedes cambiarla y traducirla como cualquier otro texto. Tu protocolo solo conserva la redacción que cambias (consulta [Palabras que aporta Network Canvas](/es/design-protocols/translating-your-protocol#words-network-canvas-supplies)). Un mensaje solo está en la sección mientras está configurada la parte de la etapa a la que pertenece, y una etapa que no tiene ninguno no tiene esta sección.

Cada mensaje puede mostrar el nombre del tipo de nodo de la etapa, tal como lo nombra el libro de códigos, y los avisos de límite también pueden mostrar su número. Cualquiera de los dos se inserta como una píldora con el botón de texto dinámico (piped text) del campo.

- **Mínimo no alcanzado** se muestra cuando quienes participan intentan continuar antes de haber añadido el número mínimo de nodos que pide la etapa. Solo aparece cuando la etapa tiene un mínimo.
- **Máximo alcanzado** se muestra cuando quienes participan han añadido el número máximo de nodos que permite la etapa. Solo aparece cuando la etapa tiene un máximo.

El mensaje que se muestra cuando no se ha podido cargar el archivo de datos de red de un panel lateral es [texto de entrevista](/es/design-protocols/translating-your-protocol#interview-text), en **Mensajes**.

</AppOnly>

### Buenas prácticas {#best-practices}

<GoodPractice>

Usa esta interfaz cuando quieras recoger pequeñas cantidades de datos de atributos al mismo tiempo que se obtiene un nodo. Puede ser más eficiente que añadir más adelante interfaces [«Formulario por álter»](../interface-documentation/per-alter-form) (un formulario para cada álter) o interfaces específicas de intérprete de nombres.

</GoodPractice>

<GoodPractice>

Asegúrate de recoger en tu formulario un valor para una variable llamada `name`, para que el [etiquetado de nodos](/es/design-protocols/key-concepts/node-labelling) funcione correctamente.

</GoodPractice>

### Qué evitar {#try-to-avoid}

<BadPractice>

Resiste la tentación de crear formularios largos con muchas preguntas. Pueden desanimar a quienes participan a nombrar más álteres, porque harán más pesada la tarea de nombrar a cada álter.

</BadPractice>

<BadPractice>

Evita los atributos que quizá sea mejor valorar en relación con otros nodos de la red. Por ejemplo, para las escalas de percepción puede ser más adecuado usar la interfaz [«Clasificación ordinal»](../interface-documentation/ordinal-bin).

</BadPractice>
