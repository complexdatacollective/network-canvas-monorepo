<Definition>
  Una forma de nodo personalizada es un dibujo propio, aportado como archivo
  SVG, que Network Canvas usa para dibujar los nodos de un tipo de nodo en
  lugar de un círculo, un cuadrado o un rombo.
</Definition>

## Cuándo usar formas personalizadas {#when-to-use-custom-shapes}

Las formas integradas sirven para la mayoría de los estudios. Un dibujo puede
ayudar cuando quienes participan necesitan reconocer de un vistazo qué
representa un nodo. Los estudios con población infantil son un caso habitual: una
casa para un hogar, una huella de pata para una mascota o un libro para un
colegio se entienden mejor que un círculo de color.

Las formas personalizadas funcionan en todos los lugares donde se dibuja un
nodo, como los generadores de nombres, los sociogramas, los contenedores (las
zonas a las que se arrastran los nodos para clasificarlos) y los formularios.
Puedes usar una como forma predeterminada de un tipo de nodo, o dejar que un
atributo decida qué forma tiene cada nodo.

![Un generador de nombres en el que cada nodo se dibuja como una pequeña ilustración, como una persona, una casa, un colegio y un perro, con la etiqueta del nodo en una placa blanca debajo.](/assets/img/custom-node-shapes/interview-name-generator.png)

<TipBox>

Las formas personalizadas necesitan un protocolo del esquema 9, es decir,
Architect 9 y además Interviewer 9 o Fresco 5. Consulta [Información sobre el
esquema de protocolo](/es/get-started/protocol-schema-information) para obtener
más detalles.

</TipBox>

## Añadir formas a un tipo de nodo {#add-shapes-to-a-node-type}

Las formas personalizadas pertenecen a un único tipo de nodo. Para añadirlas:

1. Abre el libro de códigos y edita el tipo de nodo, o crea uno nuevo.
2. Busca **Formas personalizadas** en la sección **Apariencia de los nodos**.
3. Haz clic en **Añadir una forma**. Se abre una ventana en la que puedes
   importar un archivo SVG nuevo o elegir una imagen SVG que ya sea uno de los
   recursos del protocolo.
4. Ponle un nombre a la forma. Architect propone el nombre del archivo. Cada
   forma del tipo de nodo necesita un nombre distinto del de las demás formas de ese tipo.

![El cuadro de diálogo Editar tipo de nodo de Architect. La sección Formas personalizadas muestra las formas del tipo de nodo, cada una con una vista previa que indica dónde irá la etiqueta, un campo Nombre de la forma y un botón para eliminarla, encima de un botón Añadir una forma.](/assets/img/custom-node-shapes/architect-custom-shapes.png)

Cada forma se muestra con una vista previa que incluye una etiqueta de ejemplo,
para que puedas comprobar dónde quedará la etiqueta antes de usar la forma.

Architect comprueba cada archivo cuando lo añades. Si un archivo no se puede
usar como forma, se rechaza con un mensaje que indica qué hay que cambiar.
Consulta [Preparar un archivo SVG](#prepare-an-svg-file) para conocer las
reglas.

Una vez añadida, la forma aparece junto al círculo, el cuadrado y el rombo en
todos los lugares donde eliges una forma para ese tipo de nodo:

- Como **forma predeterminada** del tipo de nodo.
- Como forma para un valor o un umbral cuando activas **Asignar formas según un
  atributo**. Consulta [Asignar la forma según un atributo de
  nodo](/es/design-protocols/key-concepts/codebook#mapping-a-node-variable-to-shape).

![Los ajustes de Asignar formas según un atributo en Architect. Bajo el encabezado Forma para cada valor, cada valor de un atributo categórico llamado type muestra su etiqueta encima de un conjunto de casillas que ofrecen el círculo, el cuadrado y el rombo, seguidos de las formas personalizadas del tipo de nodo, con la casilla elegida resaltada.](/assets/img/custom-node-shapes/architect-shape-mapping.png)

Para eliminar una forma, haz clic en su botón de eliminar. Una forma que se usa
como forma predeterminada o en la asignación de formas no se puede eliminar
hasta que elijas otra forma en su lugar.

## Preparar un archivo SVG {#prepare-an-svg-file}

Puedes dibujar una forma en cualquier herramienta que exporte SVG, como
Inkscape, Figma o Illustrator, o escribir el archivo a mano. El archivo tiene
que cumplir unas pocas reglas.

- **Dale al dibujo un `viewBox`.** El `viewBox` indica a Network Canvas el
  tamaño del dibujo. Un archivo sin `viewBox` solo se acepta si su elemento
  `svg` tiene un `width` y un `height` numéricos. Un `viewBox` cuadrado, como
  `0 0 100 100`, es el que mejor ocupa el espacio del nodo.
- **Mantén el archivo pequeño.** Una forma puede tener como máximo 50.000
  caracteres. Los dibujos sencillos, con pocos colores planos, también siguen siendo legibles cuando un nodo se dibuja a un tamaño pequeño.
- **Usa elementos de dibujo básicos.** Se admiten trazados, rectángulos,
  círculos, elipses, líneas, polígonos, texto, grupos, degradados, trazados de
  recorte y máscaras.

Architect omite todo lo que una forma de nodo no puede usar: scripts, imágenes
incrustadas, hojas de estilo, filtros, animaciones, y enlaces o referencias a
otros archivos. Cuando esto ocurre, un aviso debajo de la forma indica lo que
se ha omitido. Revisa la vista previa, porque un dibujo que dependía de alguno
de estos elementos puede verse diferente. Para evitar el problema, convierte
los efectos en formas simples y establece los colores directamente en cada
elemento (`fill="#ffd23f"`) antes de exportar.

## Colores {#colors}

Una forma puede usar sus propios colores fijos, los colores de la entrevista o
una combinación de ambos.

Para usar un color de la entrevista, escríbelo como variable CSS en un `fill`
o un `stroke`:

| Variable                                              | Color                                                            |
| ----------------------------------------------------- | ---------------------------------------------------------------- |
| `var(--node-color)`                                   | El color del tipo de nodo                                        |
| `var(--node-color-dark)`                              | Un tono más oscuro del color del tipo de nodo                    |
| `var(--node-color-seq-1)` a `var(--node-color-seq-8)` | Los ocho colores de nodo de la paleta                            |
| `var(--text)`                                         | El color del texto de la entrevista                              |
| `var(--background)`                                   | El color de fondo de la entrevista                               |
| `var(--surface)`                                      | El color de los paneles y las tarjetas                           |
| `var(--primary)`, `var(--accent)`, `var(--selected)`  | Los colores principal, de acento y de selección de la entrevista |

`currentColor` también significa el color del tipo de nodo.

Usar el color del tipo de nodo permite que un mismo conjunto de dibujos sirva
para varios tipos de nodo, y conserva el significado que el color tiene en tu
estudio. En el sociograma de abajo, cada dibujo toma su color principal del
tipo de nodo, con colores fijos para los detalles.

![Un sociograma con círculos concéntricos. Cada nodo es una ilustración cuyo color principal es el azul de su tipo de nodo, con otros detalles en colores fijos, y con vínculos dibujados entre los nodos.](/assets/img/custom-node-shapes/interview-sociogram.png)

La mayoría de las herramientas de dibujo no entienden estas variables, así que
dale a cada variable un color de respaldo para que la herramienta lo muestre:
`fill="var(--node-color, #e0457b)"`. Network Canvas ignora el color de respaldo.

## Colocar la etiqueta {#position-the-label}

De forma predeterminada, la etiqueta de un nodo se sitúa en el centro de la
forma, con el color del texto de la entrevista. Para elegir dónde va, añade un
rectángulo con el id `label-area`:

```xml
<rect id="label-area" x="16" y="64" width="68" height="28" fill="#2b2340"/>
```

El rectángulo nunca se dibuja. Su posición y su tamaño delimitan el espacio que
puede ocupar la etiqueta, y su `fill` establece el color de la etiqueta. Elige
un relleno que contraste con lo que haya dibujado detrás de la etiqueta.

### Dejar espacio para que crezcan las etiquetas largas {#give-long-labels-room-to-grow}

Las etiquetas tienen longitudes distintas, y quienes participan eligen la
mayoría de ellas. Network Canvas ajusta una etiqueta a su zona reduciendo
gradualmente el tamaño de la letra y, después, dividiendo las palabras largas.
Una etiqueta que sigue sin caber termina con puntos suspensivos en la última
línea completa. Quienes participan pueden mantener pulsado un nodo para leer la
etiqueta completa.

Si tu dibujo tiene un fondo detrás de la etiqueta, como una placa blanca o una
banda, puedes hacer que crezca con la etiqueta. Dale a ese rectángulo el id
`label-plate`:

```xml
<rect id="label-plate" x="10" y="62" width="80" height="32" rx="9" fill="#ffffff"/>
<rect id="label-area" x="16" y="64" width="68" height="28" fill="#2b2340"/>
```

A diferencia de la zona de la etiqueta, la placa de la etiqueta sí se dibuja.
Cuando una etiqueta necesita más líneas de las que caben en la zona de la
etiqueta, Network Canvas hace más alta la placa, alargándola hacia abajo, para que quepan hasta cuatro líneas. Las etiquetas más largas terminan con
puntos suspensivos, igual que antes.

La placa de la etiqueta tiene que ser un `rect` con un `height` numérico. No se
puede girar ni transformar de ninguna otra manera, y una forma solo puede tener
una. Solo tiene efecto cuando la forma también tiene una zona de etiqueta.

<TipBox>

Una placa que ha crecido sobresale por debajo de la forma. Si esperas
etiquetas largas, deja un poco de espacio bajo la línea base del dibujo, y
haz pruebas con las etiquetas más largas que prevés en el [modo de vista
previa](/es/design-protocols/preview-mode).

</TipBox>

## Ejemplo {#example}

Esta forma dibuja una casa. El tejado y la puerta usan el color del tipo de
nodo, las paredes y las ventanas usan colores fijos, y la etiqueta se sitúa en
una placa que crece.

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 100 100">
  <g stroke="#2b2340" stroke-width="3" stroke-linejoin="round">
    <rect x="18" y="32" width="64" height="34" fill="#ffe2b0"/>
    <path d="M8 37 L50 8 L92 37 Z" fill="var(--node-color, #e0457b)"/>
    <rect x="24" y="42" width="13" height="12" rx="2" fill="#a7d8f0"/>
    <rect x="63" y="42" width="13" height="12" rx="2" fill="#a7d8f0"/>
    <path d="M43 66 V50 C43 46 46 44 50 44 C54 44 57 46 57 50 V66 Z"
          fill="var(--node-color-dark, #c22f63)"/>
  </g>
  <rect id="label-plate" x="10" y="62" width="80" height="32" rx="9"
        fill="#ffffff" stroke="#2b2340" stroke-width="3"/>
  <rect id="label-area" x="16" y="64" width="68" height="28" fill="#2b2340"/>
</svg>
```

## Aspectos a tener en cuenta {#things-to-keep-in-mind}

- **Las formas son recursos del protocolo.** Cada archivo SVG se guarda en el
  archivo del protocolo junto con sus demás recursos, así que no necesitas
  conservar los archivos originales a su lado. Una misma imagen puede usarse en
  más de un tipo de nodo.
- **Quienes participan siguen necesitando la etiqueta.** Un dibujo muestra qué
  clase de cosa es un nodo, y la etiqueta dice cuál es. Deja espacio suficiente
  para ella.
- **La selección y otros estados se muestran alrededor de la forma.** Cuando un
  nodo está seleccionado, resaltado o se está vinculando, Network Canvas dibuja
  el estado alrededor de la forma, así que tu dibujo no necesita versiones
  propias para cada estado.
- **Haz pruebas a tamaños pequeños.** Los nodos se dibujan más pequeños en las
  pantallas con muchos elementos y en los teléfonos. Los detalles finos y las
  líneas delgadas pueden desaparecer.
- **El texto de un dibujo no se traduce.** Si tu protocolo tiene más de un
  idioma, no pongas palabras en la ilustración y deja que las lleve la
  etiqueta.
