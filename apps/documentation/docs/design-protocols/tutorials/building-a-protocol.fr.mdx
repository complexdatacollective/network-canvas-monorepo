## Ajouter une étape {#adding-a-stage}

Vous allez commencer par configurer une interface « Information ».

Cliquez sur le bouton **Ajouter une nouvelle étape**. Un écran s’affiche avec un menu de toutes les interfaces disponibles dans l’application. Les interfaces sont regroupées par type ; l’exemple ci-dessous montre tous les générateurs de noms disponibles.

<Screenshot axis="architect" name="add-a-stage"></Screenshot>

Chaque interface est conçue pour une tâche précise au sein d’un entretien de réseau. Pour l’instant, faites défiler la liste vers le bas et sélectionnez l’interface **Information** dans la section **Utilitaires**. Vous pouvez aussi trouver l’interface « Information » en la recherchant ou en sélectionnant le filtre **Afficher des données**.

<Screenshot axis="architect" name="information-interface"></Screenshot>

Sélectionner une interface ouvre l’éditeur d’étape, dans lequel se fait la configuration de l’interface.

### Définir le nom de l’étape {#setting-the-stage-name}

Toutes les étapes ont un nom, qui apparaît à côté de l’icône de l’étape dans la chronologie et vous aide à distinguer rapidement les étapes d’un même type. Saisissez « Welcome » (bienvenue) dans **Nom de l’étape**. Lorsque vous créez vos propres protocoles, utilisez un système cohérent pour nommer vos étapes.

### Titre de la page {#page-heading}

Le titre de la page vous permet de personnaliser un grand titre qui s’affiche en haut de votre interface « Information ». Saisissez « Welcome to the Sample Protocol » (bienvenue dans le protocole d’exemple) comme titre. Ajoutez ensuite les informations que vous souhaitez afficher à l’écran.

### Éléments {#items}

Le panneau des éléments vous permet d’ajouter différents types de contenus multimédias à l’écran. Vous pouvez ajouter des images, des vidéos, de l’audio ou du texte. Chaque ressource apparaît dans des blocs verticaux, dans l’ordre où vous les ajoutez. Vous pouvez aussi réorganiser les blocs de contenu en les faisant glisser.

Pour ajouter une ressource à cet écran, cliquez sur le bouton **Créer un élément de contenu** en bas du panneau. Un nouvel écran s’ouvre, dans lequel vous pouvez choisir parmi les types de médias disponibles. Vous pouvez ajouter du texte directement en markdown. Pour ajouter des fichiers image, audio et vidéo, sélectionnez le type, puis parcourez vos fichiers, soit à un emplacement de votre appareil, soit dans la [bibliothèque de ressources](/fr/design-protocols/key-concepts/resources).

<Screenshot axis="architect" name="edit-item"></Screenshot>

Ce tutoriel ne détaille pas la configuration de chacune des interfaces « Information » du protocole d’exemple. Vous pouvez utiliser des interfaces « Information » aussi souvent que nécessaire dans votre protocole pour décrire une tâche à venir, préparer la personne participante à une série de consignes ou lui présenter une ressource à examiner.

<AppOnly app="current">

Lorsque vous avez ajouté toutes les ressources de cette étape, cliquez sur **Modification terminée**. Votre étape est enregistrée et vous revenez à la vue de la chronologie, où l’étape que vous venez de configurer est désormais visible.

</AppOnly>

<AppOnly app="classic">

Lorsque vous avez ajouté toutes les ressources de cette étape, cliquez sur le bouton **Save and Return** (enregistrer et revenir), en bas à droite. Votre étape est enregistrée et vous revenez à la vue de la chronologie, où l’étape que vous venez de configurer est désormais visible.

</AppOnly>

## Créer des générateurs de noms {#creating-name-generators}

Vous allez maintenant créer trois étapes de générateur de noms distinctes, qui correspondent aux étapes 4, 6 et 8 du protocole d’exemple. La première utilise un générateur de noms avec ajout rapide, la deuxième un générateur avec un panneau latéral, et la dernière un générateur de noms qui utilise des formulaires.

## Générateur de noms avec ajout rapide {#name-generator-using-quick-add}

Tout d’abord, dans la vue de la chronologie, cliquez sur le bouton **Ajouter une nouvelle étape**. Dans le menu des interfaces, sélectionnez l’interface **Générateur de noms (ajout rapide)**. Lorsque la nouvelle étape s’ouvre, donnez-lui un nom comme pour l’étape précédente.

### Créer un type de nœud {#creating-a-new-node-type}

Avant de pouvoir continuer, vous devez indiquer à Architect quel type de nœud cette interface va créer. Comme il s’agit de votre premier générateur de noms, vous n’avez encore défini aucun type de nœud. <AppOnly app="current">Cliquez sur **Créer un type de nœud**, sous le sélecteur de type de nœud, pour commencer à en créer un.</AppOnly><AppOnly app="classic">Cliquez sur le bouton **Create New Node Type** (créer un type de nœud) pour commencer à en créer un.</AppOnly>

<KeyConcept title="Concept clé : les « types » de nœuds et de liens">

La flexibilité ontologique de la suite Network Canvas tient notamment à la possibilité
de modéliser un nombre illimité de types de nœuds et de liens. Ces types sont des catégories
de premier niveau qui distinguent les nœuds et les liens les uns des autres. Des types de nœuds
courants pourraient être « personne », « lieu » ou « organisation », mais c’est entièrement à vous
de décider de ces catégories.

</KeyConcept>

<AppOnly app="current">

Votre générateur de noms portera sur des personnes : nommez donc le type de nœud « Person » (personne). Chaque nouveau type de nœud reçoit la couleur suivante de la palette d’Architect, si bien que les types que vous créez l’un après l’autre se distinguent automatiquement. Vous pouvez choisir une autre couleur si vous le souhaitez, mais pour ce tutoriel, gardez celle qu’Architect a choisie.

Enfin, vérifiez l’icône de ce type de nœud. Les nouveaux types de nœuds reçoivent par défaut l’icône « ajouter une personne » de Network Canvas, qui convient à ce type de nœud : vous pouvez donc la conserver. Pour en choisir une autre, ouvrez le sélecteur d’icônes : il présente les icônes de Network Canvas, puis le jeu d’icônes Lucide, et permet d’y faire une recherche. Saisissez quelques lettres d’un nom (par exemple « building ») et choisissez parmi les icônes affichées. Cette icône apparaît dans l’entretien partout où la personne participante a la possibilité de créer un nouveau nœud de ce type.

</AppOnly>

<AppOnly app="classic">

Votre générateur de noms portera sur des personnes : nommez donc le type de nœud « Person » (personne). Vous pouvez choisir une couleur pour distinguer ce type de nœud des autres, mais dans ce cas, laissez sélectionnée la couleur corail par défaut.

Enfin, sélectionnez l’icône de personne pour ce type de nœud. Cette icône apparaît dans Interviewer partout où la personne participante a la possibilité de créer un nouveau nœud de ce type.

</AppOnly>

<Screenshot axis="architect" name="node-type"></Screenshot>

<AppOnly app="current">

Dans Architect, vous pouvez aussi choisir une **forme** pour le type de nœud ; elle s’utilise avec la couleur et l’icône pour représenter le nœud dans toutes les interfaces.

![Le sélecteur Forme d’Architect, qui propose Cercle, Carré et Losange.](/assets/img/architect-guide/node-type-shape.png)

Pour faire varier la forme des nœuds au sein d’un même type, consultez [Associer un attribut de nœud à une forme](/fr/design-protocols/key-concepts/codebook#mapping-a-node-variable-to-shape).

Cliquez sur **Enregistrer l’entité** pour créer le type de nœud et revenir à l’écran de modification du générateur de noms.

</AppOnly>

<AppOnly app="classic">

Cliquez sur **Save and Return** (enregistrer et revenir) pour créer le type de nœud et revenir à l’écran de modification du générateur de noms.

</AppOnly>

### Créer un attribut d’ajout rapide {#creating-a-quick-add-variable}

<AppOnly app="current">

Créez ensuite un attribut d’ajout rapide, qui enregistrera les données saisies pour chaque alter (chaque personne que la personne participante cite pendant l’entretien). Sauf si vous avez une bonne raison de faire autrement, cet attribut devrait s’appeler « name ». Interviewer utilisera cet attribut comme libellé de chaque nœud créé dans cette étape.

Pour le créer, cliquez sur le bouton **Sélectionner un attribut**, sous l’intitulé **Sélectionnez un attribut**. Une fenêtre s’ouvre, avec un champ de recherche, **Rechercher ou créer un attribut**, au-dessus de la liste des attributs que ce type de nœud possède déjà. Saisissez le nom de votre attribut (par exemple « name »). Comme rien ne correspond encore, la première ligne propose **Créer un nouvel attribut nommé « name ».** Choisissez-la : le nouvel attribut est créé et sélectionné comme attribut d’ajout rapide.

Ce que la personne participante saisit dans le champ d’ajout rapide est la seule information qu’elle fournit pour chaque nœud ; un attribut créé ici est donc **obligatoire** par défaut. Si vous souhaitez permettre aux personnes participantes de laisser le champ vide, désactivez **Réponse obligatoire** dans la section **Validation**, sous le sélecteur.

</AppOnly>

<AppOnly app="classic">

Créez ensuite une variable d’ajout rapide, qui enregistrera les données saisies pour chaque alter (chaque personne que la personne participante cite pendant l’entretien). Sauf si vous avez une bonne raison de faire autrement, cette variable devrait s’appeler « name ». Interviewer utilisera cette variable comme libellé de chaque nœud créé dans cette étape. Pour créer une variable, ouvrez le menu déroulant et cliquez sur **create new** (créer), puis saisissez le nom de votre variable (par exemple « name »). Cliquez sur le bouton **Create** (créer) : le nom de la nouvelle variable apparaît sélectionné comme variable d’ajout rapide.

</AppOnly>

### Créer des consignes {#creating-prompts}

Rédigez ensuite quelques questions qui inviteront la personne participante à ajouter des alters pendant l’entretien.

La plupart des étapes reposent sur la notion de « consignes », qui vous permet de définir les questions posées à la personne participante pendant l’entretien. Vous pouvez lui expliquer la tâche de la manière la plus pertinente pour votre étude.

Vous pouvez avoir plusieurs consignes dans une même étape, ou une seule consigne par étape. Envisagez de regrouper les consignes par thème et de créer une étape pour chaque thème. Par exemple, une étape « Name Generator (family) » (générateur de noms : famille) pourrait contenir des consignes sur les alters de la famille, et une étape « Name Generator (colleagues) » (générateur de noms : collègues) des consignes sur les alters du milieu professionnel.

<KeyConcept title="Concept clé : les consignes">

Les consignes peuvent comporter une mise en forme, comme du texte en gras ou en italique, pour créer
de l’emphase et du rythme. Pour appliquer cette mise en forme, utilisez la syntaxe markdown.

</KeyConcept>

Cliquez sur <AppOnly app="current">**Créer une consigne**</AppOnly><AppOnly app="classic">le bouton **Create New** (créer)</AppOnly> dans la section des consignes pour ouvrir le formulaire de modification de la nouvelle consigne.

<Screenshot axis="architect" name="edit-prompt"></Screenshot>

Votre première consigne demandera à la personne participante de citer les personnes dont elle s’est sentie proche ou avec lesquelles elle a parlé de sujets importants. Saisissez le texte « Within the past 6 months, who have you felt close to, or discussed important personal matters with? » (au cours des 6 derniers mois, pour quelles personnes avez-vous éprouvé un sentiment de proximité, ou avec qui avez-vous parlé de sujets personnels importants ?) et cliquez sur <AppOnly app="current">**Ajouter**</AppOnly><AppOnly app="classic">**Save and Close** (enregistrer et fermer)</AppOnly>.

Cliquez sur <AppOnly app="current">**Modification terminée**</AppOnly><AppOnly app="classic">**Save and Return** (enregistrer et revenir)</AppOnly> dans l’éditeur d’étape pour revenir à la vue de la chronologie, où votre nouvelle étape est visible.

## Ajout rapide avec un panneau latéral {#quick-add-with-a-side-panel}

Configurez ensuite une autre interface « Générateur de noms (ajout rapide) », mais cette fois avec un panneau latéral.

Commencez par donner un nom à l’étape, sélectionnez le type de nœud « Person » (que vous avez créé plus tôt), choisissez « name » comme attribut d’ajout rapide et créez une consigne. La consigne de cette étape sera « Within the **past 6 months,** who have you discussed **social networks research** with? » (au cours des **6 derniers mois,** avec qui avez-vous parlé de **recherche sur les réseaux sociaux** ?).

Ajoutez maintenant le panneau latéral. Cliquez sur **Ajouter un panneau** et donnez au panneau le titre « People you have previously mentioned. » (personnes que vous avez déjà citées). Ce titre s’affichera en haut du panneau latéral et donnera un contexte aux nœuds présentés à la personne participante.

Choisissez ensuite une source de données pour ce panneau latéral. Deux options s’offrent à vous : utiliser le réseau construit pendant l’entretien, ou importer un fichier de données externes (par exemple une liste, c’est-à-dire une liste prédéfinie, importée comme fichier de données, dans laquelle la personne participante choisit) qui alimentera le panneau latéral. Dans cet exemple, choisissez d’utiliser le réseau de l’entretien en cours.

<Screenshot axis="architect" name="side-panel"></Screenshot>

Vous pouvez, si vous le souhaitez, prévisualiser l’interface à ce stade, pour vérifier que les consignes et le formulaire s’affichent et fonctionnent comme prévu. Lorsque le résultat vous convient, cliquez sur continuer pour ajouter votre étape.

<AppOnly app="current">

<TipBox>

Architect enregistre votre travail automatiquement au fur et à mesure : il n’y a pas de bouton Enregistrer. Consultez [Enregistrement et sauvegarde](/fr/design-protocols/saving-and-backing-up) pour savoir comment vos protocoles sont stockés et comment les sauvegarder.

</TipBox>

</AppOnly>

<AppOnly app="classic">

<TipBox>

À tout moment pendant ce tutoriel, vous pouvez cliquer sur le bouton **Save Changes** (enregistrer les modifications) dans la barre inférieure lorsque vous êtes dans la vue de la chronologie, ou sélectionner **File → Save** (Fichier → Enregistrer) dans le menu.

</TipBox>

</AppOnly>

## Générateur de noms avec formulaires {#name-generator-using-forms}

Vous allez maintenant créer une nouvelle étape de générateur de noms qui utilise un formulaire pour recueillir des données sur les alters cités. Comme précédemment, ajoutez une nouvelle étape (en sélectionnant « Générateur de noms (avec formulaires) » dans le menu des interfaces) et donnez-lui un nom. Créez ensuite dans cette étape un nouveau type de nœud « Clinic » (établissement de santé), car la consigne portera sur des établissements de santé plutôt que sur des personnes. Une fois le type de nœud « Clinic » créé, passez à la modification du formulaire.

### Formulaire {#form}

Cette section vous permet de définir les champs qui s’afficheront dans le formulaire lorsque la personne participante crée un nœud dans ce générateur de noms.

Les champs recueillent des données sur les alters ou sur l’ego (la personne participante, au centre de son réseau), et c’est dans ces champs que l’on définit chacun des attributs recueillis.

Commencez par créer un titre pour le formulaire, afin d’indiquer à la personne participante quelles informations vous souhaitez recueillir. Saisissez le titre « Add a Clinic or Health Care Provider. » (ajoutez un établissement ou un professionnel de santé).

<AppOnly app="current">

Définissez ensuite les champs du formulaire. Cliquez sur **Créer un champ de formulaire** dans la section **Champs du formulaire**. Une boîte de dialogue s’ouvre, avec à gauche les paramètres du champ : vous y choisissez un attribut pour le champ, rédigez la question, choisissez une commande de saisie (le type de champ avec lequel un attribut est recueilli : zone de texte, curseur, cases à cocher…) et définissez la validation que vous souhaitez inclure. À droite figure un aperçu en direct de la question telle que la personne participante la verra, qui se met à jour pendant que vous travaillez. Sur un écran étroit, l’aperçu s’affiche plutôt sous les paramètres.

Pour le premier champ, vous voulez connaître le nom de l’établissement de santé que la personne participante cite. Sous **Sélection de l’attribut**, cliquez sur **Sélectionner un attribut** et choisissez « name » dans la liste ou, si le type de nœud « Clinic » n’a pas encore d’attribut « name », saisissez « name » et choisissez **Créer un nouvel attribut nommé « name ».** Ensuite, sous **Configuration du champ**, saisissez le **Texte de la question**. Dans cet exemple, utilisez la question « What is the name of this clinic? » (comment s’appelle cet établissement de santé ?).

</AppOnly>

<AppOnly app="classic">

Définissez ensuite les champs du formulaire. Lorsque vous cliquez sur **Create New** (créer) dans le panneau des champs, un nouvel écran s’ouvre et vous demande de définir une variable pour le champ, le texte de la question et une commande de saisie (le type de champ avec lequel un attribut est recueilli : zone de texte, curseur, cases à cocher…), et de sélectionner la validation que vous souhaitez inclure.

Pour le premier champ, vous voulez connaître le nom de l’établissement de santé que la personne participante cite : utilisez donc la variable « name » que vous avez créée plus tôt, en cliquant sur **Select Variable** (sélectionner une variable) puis en la sélectionnant dans la liste. Saisissez ensuite le texte du libellé de ce champ. Dans cet exemple, utilisez la question « What is the name of this clinic? » (comment s’appelle cet établissement de santé ?).

</AppOnly>

<Screenshot axis="architect" name="form-fields"></Screenshot>

<AppOnly app="current">

Dans Architect, chaque champ de formulaire peut comporter une **indication** facultative : une courte note, mise en forme en markdown, affichée sous la question pour guider la personne participante dans sa réponse.

</AppOnly>

<AppOnly app="current">

<TipBox>

De nombreux écrans d’Architect vous permettent soit de créer un nouvel attribut, soit d’en sélectionner un existant. Ils utilisent tous la même fenêtre d’attributs : cliquez sur **Sélectionner un attribut**, puis saisissez du texte dans le champ de recherche. Là où vous pouvez créer un attribut, le champ de recherche s’intitule **Rechercher ou créer un attribut**, et saisir un nom qui n’existe pas encore fait apparaître **Créer un nouvel attribut nommé « … ».** sur la première ligne. Là où vous pouvez seulement choisir un attribut existant, le champ s’intitule **Rechercher un attribut**.

Sinon, choisissez un attribut existant dans la liste. Vous pouvez utiliser les touches fléchées et la touche Entrée au lieu de la souris.

</TipBox>

</AppOnly>

<AppOnly app="classic">

<TipBox>

De nombreux écrans d’Architect vous permettent soit de créer une nouvelle variable, soit de sélectionner une variable existante. Dans ce cas, le texte à côté du champ vous l’indique généralement.

Lorsque vous voulez créer une variable, cliquez sur « Select Variable » (sélectionner une variable), saisissez le nom de la nouvelle variable et sélectionnez « Create new variable » (créer une variable) ou appuyez sur Entrée.

Sinon, cliquez sur une variable existante dans la liste.

</TipBox>

</AppOnly>

Enfin, choisissez la commande de saisie qui s’affichera pour recueillir cet attribut.

<KeyConcept title="Concept clé : les commandes de saisie">

Architect et Interviewer proposent de nombreux types de commandes de saisie (Saisie de texte, Saisie numérique, Groupe de cases à cocher, Interrupteur, Groupe de boutons radio, Groupe de boutons bascules, Sélecteur de date, Échelle de Likert, Échelle visuelle analogique).

La commande de saisie la plus adaptée à un attribut dépend de la nature précise de cet attribut, et pas seulement de son type de données. Par exemple, pour recueillir un attribut ordinal qui représente une échelle de Likert, vous préférerez peut-être une Échelle visuelle analogique ou un Groupe de boutons radio. Pour en savoir plus, consultez le [guide des commandes de saisie](/fr/design-protocols/key-concepts/input-controls).

</KeyConcept>

Comme vous demandez le nom de l’établissement de santé (un simple attribut de texte), une Saisie de texte est l’option la plus adaptée.

<AppOnly app="current">

![Le sélecteur Commande de saisie et l’aperçu en direct dans Architect.](/assets/img/architect-guide/input-control.png)

</AppOnly>

Enfin, définissez les exigences de validation de ce champ. Indiquez que ce champ de texte est obligatoire. Les options de validation disponibles varient selon le type d’attribut. Si vous ajoutez une validation « obligatoire », la personne participante doit renseigner ce champ avant de pouvoir continuer. Pour en savoir plus, consultez le [guide de validation des champs](/fr/design-protocols/key-concepts/field-validation).

<Screenshot axis="architect" name="validation"></Screenshot>

<AppOnly app="current">

Architect propose aussi l’option **Afficher les indications de validation**. Lorsqu’elle est activée, elle montre automatiquement aux personnes participantes une indication tirée des règles de validation du champ, pour qu’elles comprennent ce qui est attendu de leur réponse.

Pour essayer le champ, répondez à la question dans l’aperçu et cliquez sur **Vérifier la réponse**. L’aperçu applique les règles que l’attribut porte déjà dans le livre de codes (la définition des types de nœuds, de liens et de leurs attributs, comme le dictionnaire des codes d’une enquête) et vous montre ce qui serait indiqué à une personne participante. Répondre dans l’aperçu ne modifie pas votre protocole. Tant qu’un champ crée un nouvel attribut, comme c’est le cas ici, les règles que vous définissez en même temps ne figurent pas encore dans le livre de codes : **Vérifier la réponse** accepte donc n’importe quelle réponse jusqu’à ce que vous cliquiez sur **Ajouter** ; rouvrez ensuite le champ pour essayer ces règles.

</AppOnly>

Cliquez sur <AppOnly app="current">**Ajouter**</AppOnly><AppOnly app="classic">**Save and Close** (enregistrer et fermer)</AppOnly> pour créer votre premier champ de formulaire.

En suivant la procédure que vous venez d’apprendre, créez maintenant les deux autres champs de ce formulaire.

Créez les champs suivants, avec les commandes de saisie, les questions et les options adaptées :

- Un attribut `last_visit`, avec la commande de saisie Sélecteur de date, la question « When was your visit? » (quand a eu lieu votre visite ?) et un début de plage adapté
- Un attribut `visit_purpose`, avec la commande de saisie Zone de texte et la question « In your own words, what was the purpose of your visit? » (avec vos propres mots, quel était le motif de votre visite ?)

Une fois le formulaire terminé, configurez la consigne de l’étape. ### Nommer l’université dans la question {#naming-the-university-in-the-question}

Les deux questions parlent de « this university » (cette université). La personne participante voit un formulaire pour chaque université qu’elle a sélectionnée : la question peut donc plutôt nommer l’université sur laquelle porte le formulaire. Architect le fait en insérant le libellé du nœud dans le texte de la question, une technique appelée texte dynamique (piped text : des réponses ou des informations de l’entretien insérées automatiquement dans un texte).

Rouvrez le champ `visit_or_study`. Remplacez le texte de la question par « Did you visit » (suivi d’une espace), puis cliquez sur le bouton en forme de seringue dans la barre d’outils du **Texte de la question**, ou saisissez `{`. Un menu liste les valeurs que cette question peut afficher. Choisissez **Libellé du nœud**, la première entrée sous **Attributs contextuels**, et complétez la question avec « or study there? » (précédé d’une espace). La valeur apparaît dans la question sous la forme d’une pastille **Libellé du nœud**, et l’aperçu interactif affiche la question avec la même pastille. La question `overall_review` peut nommer l’université de la même façon.

![L’éditeur « Texte de la question », qui affiche « Did you visit [Libellé du nœud] or study there? » (avez-vous visité [Libellé du nœud] ou y avez-vous étudié ?), à côté de l’aperçu interactif du champ.](/assets/img/piped-text/value-in-question.png)

Pendant l’entretien, la pastille est remplacée par le texte affiché sur chaque nœud d’université, qui, pour cette liste, est le nom de l’université : « Did you visit Universidad Francisco Marroquín or study there? ». Le protocole d’exemple à télécharger nomme ainsi l’université dans les deux questions.

<KeyConcept title="Concept clé : le texte dynamique">

Le texte dynamique insère des informations déjà enregistrées pendant l’entretien dans le
texte que lit une personne participante : le libellé d’un nœud, un attribut du nœud ou du lien sur
lequel porte une question, un attribut de la personne participante ou la date du jour. Le libellé d’un
nœud ne manque jamais : il peut donc être inséré seul. N’importe quel attribut peut être
manquant au moment où la question s’affiche : Architect demande donc deux versions du
texte qui l’entoure, l’une pour le cas où la valeur est connue, l’autre pour le cas où elle ne l’est pas.
Pour une présentation complète, consultez [Texte dynamique](/fr/design-protocols/piped-text).

</KeyConcept>

## Créer des sociogrammes {#creating-sociograms}

Pour l’étape suivante, utilisez l’interface « Sociogramme ». Cette interface est conçue pour permettre aux personnes participantes d’interagir avec les alters produits dans les étapes de générateur de noms, de trois façons principales :

1. La disposition : la personne participante organise les nœuds dans l’espace
2. La création de liens : la personne participante peut créer des liens entre alters
3. Le basculement d’attribut : la personne participante peut désigner les alters qui possèdent un attribut booléen donné

Créez l’étape, donnez-lui un nom et sélectionnez le type de nœud « Person ».

### Positionnement des nœuds {#node-positioning}

Nous devons ensuite choisir une image d’arrière-plan pour le sociogramme. Nous pouvons choisir entre un arrière-plan par défaut à cercles concentriques et notre propre fichier image, ajouté depuis la bibliothèque de ressources ou depuis un autre emplacement de notre appareil. Pour ce premier exemple, nous choisissons l’option par défaut, avec 3 cercles, et activons « Agrandir les cercles intérieurs » pour que le centre soit proportionnellement plus grand.

Interviewer propose deux modes pour positionner les nœuds sur le sociogramme : « Mode manuel » et « Mode automatique ».

- Le **mode automatique** positionne les nœuds lorsque l’étape s’affiche pour la première fois, en simulant des forces physiques comme l’attraction et la répulsion. Cette simulation peut être mise en pause et reprise pendant l’entretien. Lorsqu’elle est en pause, la position des nœuds peut être ajustée manuellement.
- Le **mode manuel** place d’abord tous les nœuds dans une « réserve » en bas de l’écran, d’où la personne participante peut les faire glisser jusqu’à la position souhaitée.

Pour cet exemple, nous choisissons le mode manuel.

<Screenshot axis="architect" name="sociogram-background"></Screenshot>

Nous ajoutons pour l’étape une consigne dont le texte est : « Please position the people you have named amongst the concentric circles. Place people who know each other together, and put people you are closer to towards the center of the circles. » (veuillez placer les personnes que vous avez citées parmi les cercles concentriques. Placez ensemble les personnes qui se connaissent, et rapprochez du centre des cercles les personnes dont vous êtes le plus proche).

Vous verrez que, lorsque vous créez une consigne dans le sociogramme, vous avez la possibilité de définir un attribut de disposition.

L’attribut de disposition sert à enregistrer les coordonnées X/Y des nœuds lorsque la personne participante les positionne à l’écran. Si votre sociogramme comporte plusieurs consignes, vous pouvez utiliser le même attribut de disposition pour chacune (les nœuds restent alors à la position où la personne participante les a placés au départ) ou créer un nouvel attribut de disposition pour chaque consigne (la personne participante devra alors repositionner les nœuds à chaque fois). Dans cet exemple, nous créons un attribut « sociogram_layout » pour cette étape.

<Screenshot axis="architect" name="sociogram-layout"></Screenshot>

Pour finir, nous cliquons sur <AppOnly app="current">**Ajouter**</AppOnly><AppOnly app="classic">« Save and Close » (enregistrer et fermer)</AppOnly> pour fermer l’éditeur de consigne, puis sur <AppOnly app="current">**Modification terminée**</AppOnly><AppOnly app="classic">« Save and Return » (enregistrer et revenir)</AppOnly> pour enregistrer l’étape.

## Création de liens {#edge-creation}

Nous allons créer une autre étape « Sociogramme » pour tester la création de liens. Pour cette étape, nous utilisons le type de nœud « Person » et l’arrière-plan à 3 cercles concentriques, avec « Agrandir les cercles intérieurs » activé.

Nous créons notre première consigne, « Please connect any two people who might spend time together without you being there » (veuillez relier toutes les paires de personnes qui pourraient passer du temps ensemble en votre absence), et nous utilisons l’attribut sociogram_layout que nous avons déjà créé.

Nous allons maintenant activer la création de liens dans une consigne du sociogramme : nous activons l’interrupteur « Interaction avec les nœuds » et, sous « Type d’interaction », sélectionnons « Création du lien »<AppOnly app="classic"> (dans Architect Classic : l’interrupteur « Interaction Behavior » (comportement d’interaction) et l’option « Edge Creation » (création de liens), dans la section « Edge Display and Creation » (affichage et création des liens))</AppOnly>.

Le sociogramme est le principal endroit de l’entretien où les liens sont créés. Une consigne de sociogramme ne peut créer qu’un seul type de lien à la fois, mais notez qu’elle peut en afficher plusieurs.

Lorsque plusieurs types de liens sont affichés et que la personne participante crée un nouveau lien là où un lien existe déjà, le fonctionnement est simple : le lien existant est remplacé visuellement par le nouveau type de lien. Les deux liens restent enregistrés dans le réseau de l’entretien. Supprimer ce nouveau lien rétablit l’affichage du type de lien visible auparavant (un seul type de lien peut être créé ou supprimé dans une consigne).

Vous pouvez envisager d’utiliser cette fonctionnalité pour construire un réseau progressivement, en permettant à la personne participante de s’appuyer sur l’« échafaudage » visuel des liens existants pour repérer rapidement où en créer de nouveaux.

Dans le champ suivant, nous allons soit créer un nouveau type de lien, soit en sélectionner un existant. Comme nous n’avons encore créé aucun type de lien, nous créons un nouveau type appelé « know » (se connaissent), qui correspond à la consigne.

Nous cliquons sur <AppOnly app="current">**Ajouter**</AppOnly><AppOnly app="classic">« Save and Close » (enregistrer et fermer)</AppOnly> pour revenir à l’éditeur du sociogramme.

<Screenshot axis="architect" name="edge-creation"></Screenshot>

## Sociogramme : basculer un attribut {#sociogram-toggling-an-attribute}

Dans la dernière étape « Sociogramme » de ce protocole, nous allons mettre en place le basculement d’attribut, c’est-à-dire l’action qui permet à une personne participante de faire passer un attribut booléen à « true » (vrai) ou à « false » (faux) en touchant un nœud.

Une fois encore, nous créons l’étape, lui donnons un nom, sélectionnons le type de nœud « Person » et utilisons l’arrière-plan à 3 cercles concentriques, avec « Agrandir les cercles intérieurs » activé.

Nous créons ensuite une nouvelle consigne, avec le texte « Please select anyone who you have asked for advice within the previous 6 months » (veuillez sélectionner les personnes à qui vous avez demandé conseil au cours des 6 derniers mois). Réutilisez l’attribut de disposition (« sociogram_layout ») que nous avons créé plus tôt.

Nous ne voulons pas activer la création de liens dans cette consigne, car cela désactiverait la fonction de basculement d’attribut (les deux modes s’excluent mutuellement). Nous pouvons toutefois afficher des liens pour aider la personne participante à repérer les nœuds.

Pour cela, sélectionnez « Know » et « Conflict » sous « Liens affichés ».

Nous avons maintenant terminé la configuration de cette étape « Sociogramme ».

## Créer une étape « Classement ordinal » {#creating-an-ordinal-bin}

Vous voulez maintenant créer une interface « Classement ordinal » pour interroger rapidement et efficacement la personne participante sur la fréquence de ses contacts avec chaque alter. Dans la vue d’ensemble de la chronologie, ajoutez une nouvelle étape avec l’interface « Classement ordinal ».

<KeyConcept title="Concept clé : les « cases » et la « réserve »">

Par convention, le logiciel Network Canvas utilise deux termes pour les zones entre lesquelles on fait glisser les nœuds dans les interfaces « Classement ordinal », « Classement par catégories » et « Sociogramme ».

La réserve est l’endroit où se trouvent d’abord les nœuds, avant d’avoir été placés ou déplacés. Les cases sont les zones _vers_ lesquelles on place ou fait glisser les nœuds. C’est là que les nœuds se retrouvent au final.

Dans les cases comme dans la réserve, on peut définir l’ordre de tri des nœuds qu’elles contiennent. Vous pouvez vous en servir (par exemple) pour que la réserve affiche d’abord les nœuds qui ont un certain attribut, comme la proximité. Cela peut faciliter une tâche comme le positionnement des nœuds sur un sociogramme.

</KeyConcept>

Comme pour les interfaces précédentes, commencez par nommer l’étape (« Contact Frequency », fréquence des contacts) et par sélectionner notre type de nœud (« Person »).

### Configurer les préréglages {#configuring-presets}

Les préréglages (des configurations d’affichage du réseau définies dans une étape « Narration ») vous permettent de faire ressortir visuellement certains éléments du réseau d’une personne participante, comme les nœuds regroupés selon une caractéristique d’attribut ou les relations entre alters (les liens). Une fois configurés sur cet écran, les préréglages s’affichent sous forme de menu, où chaque option peut être activée ou désactivée.

Configurons maintenant les préréglages de notre protocole d’entretien d’exemple. Allez dans la section de l’éditeur de l’étape « Narration » intitulée « Préréglages de visualisation » et appuyez sur le bouton « Créer un préréglage ». Nous donnons au préréglage le libellé « Sample Preset » (préréglage d’exemple). Ce libellé apparaîtra en haut du menu que voit la personne participante dans cette étape.

Nous sélectionnons ensuite, dans la section « Disposition des nœuds », un attribut qui servira à positionner les nœuds pour ce préréglage. Nous pouvons soit créer un nouvel attribut de disposition pour cet écran, soit en utiliser un existant. Ici, nous utilisons l’attribut « sociogram_layout » que nous avons créé plus tôt.

Si nous avons recueilli des données sur un attribut catégoriel et que la personne participante a attribué une de ses valeurs à au moins deux nœuds, nous pouvons visualiser ce regroupement dans l’interface « Narration ». La section « Regroupement des nœuds » affiche tous les attributs catégoriels disponibles dans notre protocole. Dans cet exemple, nous choisissons l’attribut « group ».

<Screenshot axis="architect" name="edit-preset2"></Screenshot>

## Proposer le protocole dans plusieurs langues {#offering-the-protocol-in-more-than-one-language}

[Traduire votre protocole](/fr/design-protocols/translating-your-protocol) décrit chaque outil en détail et aborde les considérations méthodologiques qui doivent guider la traduction d’un protocole pour une véritable étude.

### Ajouter une langue {#adding-a-language}

Ouvrez la page **Langues** depuis la barre de navigation en haut de l’éditeur. Elle indique l’anglais américain comme seule langue du protocole, marquée **Par défaut**. L’espagnol apparaît maintenant à côté de l’anglais américain, avec un badge **Traductions manquantes** et le nombre de textes déjà traduits dans cette langue. Le texte que vous avez rédigé doit encore être traduit. Tant qu’il ne l’est pas, les personnes participantes qui utilisent l’espagnol voient à la place le texte en anglais américain.

![La page Langues après l’ajout de l’espagnol. L’espagnol porte un badge Traductions manquantes.](/assets/img/architect/localization/languages-page.png)

### Traduire l’étape « Welcome » {#translating-the-welcome-stage}

Revenez à la liste des étapes, où une note indique désormais qu’une partie du contenu n’est pas encore traduite en espagnol, et ouvrez l’étape **Welcome**. Comme le protocole a deux langues, chaque champ de texte de l’éditeur d’étape possède un menu de langue. Choisissez **espagnol** dans le menu à côté de **Titre de la page**. Tous les champs de l’éditeur passent ensemble à l’espagnol. Le champ du titre est vide, et une note en dessous explique que les personnes participantes qui utilisent l’espagnol verront le texte en anglais américain.

![Le champ « Titre de la page » de l’étape « Welcome », avec l’espagnol choisi pour la modification, avant sa traduction.](/assets/img/architect/localization/editor-missing-translation.png)

Saisissez « Bienvenida » comme nom de l’étape et « Te damos la bienvenida al protocolo de ejemplo » comme titre de la page, puis cliquez sur **Modification terminée**.

Traduire étape par étape convient aux protocoles courts. Pour un protocole plus long, ou lorsque la traduction est faite par une autre personne que celle qui a rédigé le protocole, le tableau des traductions est plus efficace. Revenez à la page **Langues** et cliquez sur **Ouvrir le tableau des traductions**. Le tableau liste chaque texte du protocole à côté de sa traduction dans chaque langue, et les textes que vous venez de traduire apparaissent dans la colonne de l’espagnol. Les textes non traduits affichent, en caractères plus clairs, le texte en anglais américain que les personnes participantes verront à la place.

### Laisser les personnes participantes choisir leur langue {#letting-participants-choose-their-language}

Par défaut, un entretien s’ouvre dans la langue qui correspond le mieux aux paramètres du navigateur ou de l’appareil de la personne participante. Veillez à enregistrer votre fichier. Le nom du fichier du protocole l’identifiera de manière unique dans l’application Network Canvas Interviewer et dans [Fresco](/fr/collect-data/fresco/using-fresco#uploading-protocols).

Les protocoles créés dans Architect Classic utilisent le schéma 7 : ils s’exécutent donc dans **Interviewer Classic**. **Fresco** et **Interviewer** les exécutent aussi : ils migrent automatiquement un protocole en schéma 7 vers le schéma 8 lorsque vous le téléversez (envoyez vers le serveur) ou l’importez. Pour utiliser les fonctionnalités du schéma 9, mettez d’abord le protocole à niveau dans Architect.

Il existe de nombreuses façons de passer de la construction du protocole dans Architect à son déploiement.

#### Interviewer {#interviewer-1}

- Dans l’application Interviewer, importez le fichier du protocole directement depuis un emplacement de votre ordinateur.
- Hébergez le fichier du protocole sur un serveur web, puis, dans l’application Interviewer, importez le fichier du protocole depuis une URL.

#### Fresco {#fresco-1}

- Pour déployer le protocole dans Fresco, consultez notre tutoriel [Utiliser Fresco](/fr/collect-data/fresco/using-fresco#uploading-protocols).
