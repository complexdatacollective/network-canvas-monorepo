# Registry installation contract

The signed Studio installer owns configuration and consumes these files as a required independent service overlay. It copies them into `deployment/registry/`, adds `deployment/registry/compose.yml` to the primary Compose file list, and enables the registry profiles. The primary ingress owns a distinct HTTPS registry hostname and forwards it to `registry:3000`. The managed service uses the same registry image on its required container PaaS; this Compose overlay is the self-hosted reference only.

Before writing `postgres-init.sql`, replace its one `/* REGISTRY_RUNTIME_ROLES */` marker with `runtimeRolesSql(['registry_app', 'registry_operator', 'registry_backup'], 'Template Registry')` from `@codaco/studio-sync/role-bootstrap`. Refuse a missing or repeated marker. Do not duplicate or freeze the role validation into migration history. PostgreSQL's initializer executes only for a fresh volume; an existing database requires reviewed explicit operator provisioning.

After `\connect registry`, replace the one `/* REGISTRY_LARGE_OBJECT_PRIVILEGES */` marker with the same shared module's `revokeLargeObjectPrivilegesSql(['registry_app', 'registry_operator', 'registry_backup', 'registry_migrator', 'registry_runtime', 'registry_operations', 'registry_backup_login'])`. Refuse a missing or repeated marker. The PostgreSQL administrator executes this in the dedicated registry database to remove PUBLIC and direct creation/import/export capabilities. The migrator and runtime must not receive administrative credentials to perform it. Apply the same administrator provisioning after a restore, before security validation.

Generate independent random values for `REGISTRY_POSTGRES_PASSWORD`, `REGISTRY_MIGRATION_PASSWORD`, `REGISTRY_DATABASE_PASSWORD`, `REGISTRY_OPERATOR_PASSWORD`, `REGISTRY_BACKUP_PASSWORD`, `REGISTRY_AUTH_SECRET`, `REGISTRY_MINIO_ROOT_USER`, `REGISTRY_MINIO_ROOT_PASSWORD`, `REGISTRY_S3_ACCESS_KEY_ID`, and `REGISTRY_S3_SECRET_ACCESS_KEY`. Generated password/key values must be URL-safe so they can be interpolated into the explicit connection URLs. `REGISTRY_IMAGE` and `MINIO_IMAGE` come from the signed release. The operator supplies `REGISTRY_DOMAIN` and `REGISTRY_MAIL_FROM`, plus exactly one of `REGISTRY_SMTP_URL` or `REGISTRY_POSTMARK_SERVER_TOKEN`. The optional `REGISTRY_POSTMARK_MESSAGE_STREAM` requires Postmark and otherwise defaults to `outbound`. Configure a verified sender or domain for Postmark. Both transports validate the configured sender before admission, retain typed uncertain delivery outcomes, and own bounded shutdown.

The installer owns these values in its private configuration with mode `0600`. Compose selects each service's environment explicitly; never inject the complete configuration as an `env_file`. The HTTP process gets the two restricted runtime database URLs, its authentication secret, mail configuration and scoped object-store identity. Migration and database administrator credentials never enter that process. Retain the authentication secret and storage/database recovery credentials in independent operator custody. The registry holds no Studio PII, integration-encryption or blind-index roots; those remain in the independent Studio key custody set.

Database `registry` belongs to `registry_migrator`. `registry_runtime` can SET only `registry_app`; `registry_operations` can SET only `registry_operator`; `registry_backup_login` can SET only the SELECT-only `registry_backup`. Every LOGIN is NOINHERIT without administration or replication attributes. CONNECT is committed for those four logins while database admission is disabled. The runtime refuses a missing/stale fingerprint or app/operator connections to different databases, including restored clones with the same installation identifier.

The administrator must revoke database TEMPORARY from PUBLIC and every restricted runtime/backup role and LOGIN, including after restore. This prevents implicit temporary-namespace CREATE before any temporary objects exist. Migration and backup verification refuse TEMPORARY or catalog privileges beyond the reviewed PostgreSQL 18 stock baseline; they never repair these grants automatically. Keep administrator provisioning separate from migration and backup verification. Pool-based backup verification uses one read-only transaction with a ten-second deadline; an explicitly supplied client retains its caller's transaction ownership.

Run `docker compose --profile registry --profile registry-operator run --rm registry-migrate` before starting the HTTP service. It runs immutable checked-in migrations; startup never reconciles a schema. To grant or revoke an existing verified registry account's operator status, run the same service with `--entrypoint node registry-migrate dist/operator.js grant USER_ID` or `revoke USER_ID`. This requires the database owner and atomically appends an immutable audit event. It never creates an account or bypasses email verification.

Readiness is `/readyz`; liveness is `/healthz`. Shutdown stops admission, drains sockets for at most ten seconds, waits for the current bounded cleanup pass, and enforces a total process deadline of 25 seconds. The overlay grants 30 seconds before container termination. Artifact intake and downloads have separate bounded capacities; publish/archive size, storage and durable account/mail limits are configured in the server.

This overlay's HTTP object-store connection is explicitly permitted with `REGISTRY_S3_INSECURE_PRIVATE_NETWORK=true` on the internal `registry-data` network. External managed object stores require HTTPS with that option omitted. Neither object API nor database/console ports are published. The bucket remains private; its runtime identity can list the dedicated bucket and get/put/delete only `template-artifacts/*`. It cannot administer users, policies, buckets or other object namespaces.

Recovery must stop registry admission and the cleanup worker, quarantine `registry_runtime`, `registry_operations`, and `registry_migrator`, and refuse surviving writers before capture. Dump `registry` using `registry_backup_login --role=registry_backup`, retain its migration history and fingerprint, and capture the quiesced independent `registry-minio` volume. Retain the registry image and all infrastructure image bytes with the other signed installation artifacts. Restore into separate empty registry volumes and independently named networks, and verify hashes and required independently held configuration. While HTTP and workers remain stopped on the isolated target, restore the enrolled identities' LOGIN attributes and run the migration lane's no-op security checks and dedicated backup verifier. Temporary NOLOGIN attributes do not satisfy the reviewed enrollment contract. Run the populated registry smoke before reopening external admission. These source files and local tests do not qualify provider PITR, independent immutable backups, or a managed restoration drill.
