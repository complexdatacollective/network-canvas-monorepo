# Studio distribution caller

Local implementation for #1243. The concrete Docker qualifier and manually dispatched production workflow are implemented. Actual qualification of signed published artifacts remains incomplete; no workflow has been dispatched and no release has been published by this work.

`scripts/studio-distribution-caller.mjs` composes the existing publication, GitHub store, admission, historical-manifest authentication, image preparation and signature-verification modules. It fetches main and immutable tags before every admission. It preserves the publisher's four gates, exact asset readback and source reservation. Historical manifests and their retained SBOMs reach preparation only after authentication. The supplied absolute Cosign, Crane and Syft paths come from the separately verified tool bootstrap.

The workflow holds the non-cancelling distribution lock for this entire invocation. The default isolated Docker qualifier uses no live production credentials. A qualification receipt binds the candidate source and manifest digest, successful fresh installation and populated recovery, and exactly the authenticated oldest/immediately previous upgrade sources. Missing, failed, substituted or incomplete receipts prevent the GitHub draft and asset writes. The receipt is an internal contract with the qualifier, not cryptographic evidence that an installation ran; the actual harness must exercise the operations and preserve its execution evidence.

The caller does not supply an environment-selected command, success stub or automatic waiver for unavailable qualification. The manual workflow refuses any ref other than main, installs pinned release tools, and repeatedly requires the dispatch source to equal the freshly fetched main tip. Managed provisioning has its own unresolved provider and budget gates.

Qualification receives isolated manifest, artifact and historical-evidence copies and a read-only asset reader. Expected candidate and upgrade identities are captured before invoking it. Consuming or annotating these inputs cannot change the publication bytes, metadata or required upgrade set.

Image preparation now builds into random staging tags and authenticates an atomic signed checkpoint before creating canonical source tags. A retry verifies retained signatures and exact bytes instead of adopting unsigned image evidence. The GitHub checkpoint store rejects legacy or unknown assets on every operation. A composed preparation/store test reproduced an unsupported legacy-name lookup, then passed fresh preparation and an exact retry after that lookup was removed. The corresponding legacy-asset control still refuses all image preparation and signing. The checkpoint is bounded to 64 MiB; real release qualification must also demonstrate that all six SBOMs fit this limit.

Validation: 39 caller and publication tests exercise the real publication state machine with isolated I/O boundaries. They cover all four fresh gates, history and pinned-tool propagation, failed boundaries, malformed qualification, mutable-input isolation, and eligibility withdrawal after draft readback. Separate disposable module mutations remove the fresh-install and manifest-binding checks; the corresponding refusal tests then fail with the expected missing-rejection assertion. These tests do not claim live registry publication, Sigstore signing or installation/recovery qualification.

After composing Registry installer/recovery and signed image checkpoints, 154 focused tests passed across preparation, store, publication, caller, image preparation, installer archive/bundle/operation and private smoke. Studio server, Registry and Studio sync types, Knip, targeted lint and formatting passed. The populated combined Docker rehearsal remains a separate completion gate.

The concrete qualifier stages authenticated bundles in private directories, executes a fresh installation and populated recovery, and seeds preserved owner, team, participant and object canaries before each supported historical upgrade. It verifies restored object hashes, key-purpose failures, invalidated sessions and closed writer logins. Local controls reproduce the Compose overlay bug where an explicit overlay hid the base files; the wrapper now materializes every base file and refuses an implicit default. The root integration passed 56 caller, qualifier, Docker-wrapper, workflow and admission controls. These are fixture and guard results, not a signed-artifact recovery receipt.

The first real workflow run must prove write access to all six controlled GHCR repositories and anonymous read access to the resulting signed images. The isolated recovery qualifier deliberately has no registry credentials. Publication still requires released dependency provenance, successful source CI, consumed changesets, authenticated history, exact image and installer signatures, and the full Docker drill. The pending canonical migration integration must be resolved and reviewed before preparing a release candidate.
