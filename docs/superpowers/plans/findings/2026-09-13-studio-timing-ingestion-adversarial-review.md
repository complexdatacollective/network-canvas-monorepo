# Studio timing ingestion adversarial review

The initial timing rollup treated freshness as a timestamp and maintained wave and stage rows as independent work queues. That permits a worker to read one source state and then clear a later write, lets a stage claim disappear during the wave rebuild, carries retry exhaustion into unrelated future writes, and makes an absent stage row look like successful completion. The corrected contract gives each wave one monotonically increasing dirty generation: every timing or monitored-source write locks the wave row before changing source state and advances that generation; a worker claims one generation, reads and rewrites all wave and stage metrics while holding the same row lock, and clears work only when the claimed generation still matches and its lease is active. Stage rows are stable derived records updated by upsert (and obsolete rows are removed only inside that serialized rebuild), not an independent queue. A new dirty generation resets retry and failure state. Duration milliseconds are rounded to the nearest integer at ingestion, including the retained total, so the JSON contract and bigint aggregates have one precision rule. Stage completion and abandonment come from each stage's recorded exit direction, and missing-item counts come only from explicit persisted missingness values in node, edge, and ego attributes; an empty attribute object does not mean missing.
